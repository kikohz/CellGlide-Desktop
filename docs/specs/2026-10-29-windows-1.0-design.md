# CellGlide Windows 1.0 设计

日期：2026-10-29
状态：用户已确认（2026-10-29）。
前置：`docs/windows/HANDOFF.md`（用户已定事项）、`docs/windows/research-net.md`、`docs/windows/research-apple.md`、`docs/specs/2026-10-16-linux-1.0-full-design.md`（以下称「Linux 完整版设计」）。Mac 参考实现在 CellProxy 仓库，写作 `CellProxy:路径`。

本文件只写 Windows 的技术设计。功能范围、界面页面、文案以 Linux 完整版设计 §4 为准，下文只写 Windows 上的不同之处。

## 1. 意图

Linux 1.0.0 已经发布。Windows 版要让 Windows 用户得到同样完整的产品：插上 iPhone 就能用手机的蜂窝网络上网，有托盘面板、手机卡片、测速、DNS 泄漏测试、连接记录、诊断、设置和关于。

技术上要做到两点：

- **核心逻辑只有一份。** 连 iPhone、状态机、健康判定、测速和泄漏检测引擎、诊断打包、全部文案，都继续由 Rust 的 cg-* crate 提供，Windows 只补平台层。
- **界面是地道的 Windows 应用。** WinUI 3（C#）只负责显示和交互，不重新实现业务逻辑。

## 2. 目标、非目标与反目标

**目标**
- 功能对齐 Linux 1.0（Linux 完整版设计 §4.1–4.9）。
- 同时支持 x64 和 ARM64，两种架构都由 CI 公开构建。
- 一行 PowerShell 安装、升级、卸载，同时提供 zip 直链。

**非目标**
- MSI / MSIX 安装包、应用内自动更新、代码签名（第一版不签，见 HANDOFF）。
- 自带 usbmuxd、WinUSB 驱动或任何 Apple 组件。
- 分流、流量去向地图、西班牙语（与 Linux 一致）。
- 经网关可达的私有网段绕过路由（见 §5.4）。
- USB 链路速率显示（Linux 读 sysfs；Windows 版第一版不显示这一项）。

**反目标**（技术上能用也算失败）
- 改动 CellGlide 自己网卡以外的任何网络设置：其他网卡的 DNS、跃点、路由，NRPT，hosts，Winsock 目录。
- 进程崩溃后在系统里留下会影响上网的状态。
- 为界面功能放宽服务的授权边界：服务以 LocalSystem 运行，界面和测速仍是普通用户进程。
- 在 C# 里重复写一套 Rust 已有的逻辑或文案。
- 读不到的数据显示成假的或 0（沿用 Linux）。

## 3. 用户已定事项（摘自 HANDOFF，不再讨论）

1. 功能对标 Linux 1.0。
2. x64 + ARM64。
3. 依赖微软商店的「Apple 设备」应用提供的 Apple Mobile Device Service（`127.0.0.1:27015`），不带驱动。服务不存在时，安装脚本提示安装，或在用户同意后用 `winget --source msstore` 安装。
4. PowerShell 一行命令安装和卸载，另给 zip 直链，不做 MSI。
5. 第一版不签名。
6. WinUI 3（C#）界面 + Rust 核心：Rust 系统服务、Rust 动态库 `cellglide.dll`（C 接口）、C# 界面。托盘用 H.NotifyIcon，自包含部署，不打包成 MSIX。
7. 开发在这台 Windows 测试机上做。

## 5. 网络接管

### 5.1 转发引擎：ipstack + 自己的 SOCKS5 胶水层（cg-netstack）

Mac 和 Linux 用 hev-socks5-tunnel。它在 Windows 上只能用 MSYS2 编译，只有 x64，不能链进 MSVC 构建的 Rust 程序（research-net §1.2）。Windows 1.0 改用 Rust 用户态协议栈。

**选择：smoltcp 加自己写的 SOCKS5 胶水层，放进新 crate `cg-netstack`，不用 tun2proxy。**（2026-10-30 修订：原定 ipstack，W1 实现时发现它不支持 TCP 半关闭、会丢弃带数据的 FIN 包，改用 smoltcp。）理由：

- tun2proxy 自带的 DNS、HTTP 代理、路由配置我们都要关掉，留下的只是 ipstack 加一层 SOCKS5 客户端。
- 自己写可以精确对齐 hev 的参数：MTU 1500、TCP 读写超时 1800 s、UDP 空闲 30 s、UDP 走标准 SOCKS5 UDP ASSOCIATE（对应 hev 的 `udp: 'udp'`）。SOCKS5 编解码 `cg-protocol::socks` 已经有了。
- 引擎只接 `AsyncRead + AsyncWrite` 的包设备，与 wintun 无关，可以在 Linux 和 macOS 的 CI 上用内存设备测试，还能在 Linux 上和 hev 跑同一组流量做对比（§12.1）。

接口：

```rust
pub struct NetstackConfig { pub mtu: u16, pub socks: SocketAddr, pub tcp_timeout: Duration, pub udp_idle: Duration }
pub async fn run<D: AsyncRead + AsyncWrite + Unpin + Send>(device: D, config: NetstackConfig, stop: CancellationToken) -> io::Result<()>;
```

`cg_core::tunnel` 新增 `netstack_config(socks_port)`，常量来自与 `hev_config` 同一组定义，并加一条测试：两者的 MTU、超时一致。

**这是与 Mac / Linux 的有意差异**：AGENTS.md 要求「hev 设置与 Mac 一致」。Windows 上改为「转发引擎的参数与 hev 设置一致」，并更新 AGENTS.md（§13）。hev 的 MSVC 支持（上游 PR #337 和 hev-task-system #17）合并后，再评估是否换回 hev。

### 5.2 虚拟网卡：wintun

- 随包带官方签名的 `wintun.dll`（0.14.1，按架构选 amd64 / arm64），连同 `wintun-LICENSE.txt` 放在 `C:\Program Files\CellGlide\`。`scripts/fetch-wintun.ps1` 下载官方 zip 并核对写在脚本里的 SHA256。不放进仓库。
- 加载：`LoadLibraryExW` 带 `LOAD_LIBRARY_SEARCH_APPLICATION_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`。
- 网卡：`WintunCreateAdapter("cellglide0", "CellGlide", GUID)`，GUID 固定为 `{E490EEF2-2CB0-4A80-B341-BF929C2E56B3}`，写成 `cg_core::tunnel` 旁边的 Windows 常量。固定 GUID 让 NLA 记录和 `Tcpip\Parameters\Interfaces\{GUID}` 只有一份。
- 会话环形缓冲 4 MiB。两个专用线程分别收包、发包，经通道接到 cg-netstack 的设备适配器上。
- 停止时按 WireGuard 的顺序：清空本网卡的 DNS、路由、地址，结束会话，`WintunCloseAdapter`。崩溃时网卡随进程句柄消失（research-net §2.3，W0 实测确认）。
- 服务启动时 `WintunOpenAdapter("cellglide0")`，能打开说明有残留，先关闭。

### 5.3 地址、路由、跃点

全部只写在 cellglide0 的 LUID 上，用 IP Helper（`CreateUnicastIpAddressEntry`、`CreateIpForwardEntry2`、`SetIpInterfaceEntry`），不调用 netsh。

- 地址：`198.18.0.1/32`、`fd6c:6779:6465::1/128`，DAD 关闭（`DadTransmits = 0`），这样地址一加上就可用。
- 路由：`0.0.0.0/1`、`128.0.0.0/1`、`::/1`、`8000::/1`，下一跳为未指定地址，Metric 0。常量直接用 `cg_core::tunnel` 里的，与 Mac 一致。
- 接口：MTU 1500，`UseAutomaticMetric = false`，`Metric = 0`，`RouterDiscoveryDisabled`。
- IPv6 加不上（系统禁用了 IPv6）时降级为仅 IPv4，记日志，与 Linux 相同。

### 5.4 局域网绕过

`TunnelPlan.bypass` 在 Windows 上不额外加路由。本网段的 on-link 路由和多播路由本来就挂在物理网卡上、前缀比 /1 长，自然留在本地。经网关可达的其他私有网段会走手机，这一点与 Mac 不同，写进已知差异。要加的话得在物理网卡上写路由，违背「只改自己的网卡」，留待有需求再评审。

### 5.5 手机路径

usbmux 走 `127.0.0.1:27015`，转发器和 SOCKS 都在环回上，环回的 /8 路由比 /1 更具体，永远进不了隧道，不需要任何绕过。

## 6. 服务与 IPC

### 6.1 服务

- `cellglide-service.exe`，服务名 `CellGlide`，显示名「CellGlide」，LocalSystem，自动启动。
- 失败后重启：`sc.exe failure CellGlide reset= 86400 actions= restart/2000/restart/5000/restart/30000`。
- `sc.exe sidtype CellGlide unrestricted`；`sc.exe privs` 收紧到实测需要的最小集合（W0 确定）。
- 电源事件：接受 `SERVICE_ACCEPT_POWEREVENT`，`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC` 接到现有的睡眠处理（`sleep.rs` 对 logind 做的事）。另外按单调时钟与墙钟的跳变判断睡眠，覆盖 Modern Standby 收不到通知的情况。
- `--console` 参数在前台运行，供开发调试。
- 数据目录 `C:\ProgramData\CellGlide\`：`settings.json`、`health\`、`logs\`。ACL 只允许 SYSTEM、Administrators 和服务 SID 写入，Users 只读 `health\`（由安装脚本设置，§10）。
- 日志：tracing 写到 `logs\service.log`，按天滚动、保留 7 天。诊断从这里取日志，对应 Linux 读 journal。

### 6.2 传输：命名管道

- 管道名 `\\.\pipe\cellglide-control`，协议不变：每行一个 JSON 对象，消息类型与 Linux 共用 cg-ipc。
- 服务端：`tokio::net::windows::named_pipe`，第一个实例用 `first_pipe_instance(true)`，拒绝远程客户端，SDDL 为 `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;GRGW;;;IU)`，即只有 SYSTEM、管理员和交互式登录用户能连。
- 客户端（cg-ipc，CLI 和 cellglide.dll 共用）：连接后用 `GetNamedPipeServerProcessId` 取服务端进程，确认其令牌是 LocalSystem，否则拒绝。这样服务没在运行时，别的程序抢先建同名管道也冒充不了服务。
- 不用 AF_UNIX：Windows 上取不到对方身份，tokio 也不支持。

### 6.3 授权

每个连接建立时，服务端用 `GetNamedPipeClientProcessId` → `OpenProcessToken` 读出用户 SID、会话 ID、是否管理员。

| 请求 | 谁可以 |
|---|---|
| Hello、Status、Subscribe、History、Doctor | 任何能连上管道的用户（即交互式登录用户） |
| Connect、Disconnect、SetSettings、Diagnostics | 管理员，或者所在会话处于活动状态（`WTSQuerySessionInformation` 的 `WTSConnectState == WTSActive`，覆盖本地控制台和远程桌面）的用户 |

被拒绝时回 `Reason::NotAllowed`（新增，对应 Linux 的 `NotInGroup`）。Linux 的「cellglide 组」概念在 Windows 上没有对应物，不建组。

### 6.4 doctor 检查项

`CheckId` 新增 Windows 项，Linux 的 `Group`、`Resolved`、`Polkit`、`PolkitRule` 在 Windows 上不出现：

- `Service`：CellGlide 服务在运行
- `AppleService`：Apple Mobile Device Service 已安装（注册表 `HKLM\SYSTEM\CurrentControlSet\Services\Apple Mobile Device Service`）且在运行，并说明是商店版还是 iTunes 版
- `Usbmuxd`：`127.0.0.1:27015` 能连上并回应 ListDevices
- `Phone`、`Trust`：与 Linux 相同
- `Wintun`：`wintun.dll` 在且签名有效
- `Dns`：解析器端口 `198.18.0.1:53` 没被占用（ICS / Hyper-V 的 SharedAccess 可能占 53）

每项不通过时给出修复提示，例如 Apple 设备没装时给出商店链接和 winget 命令。

## 7. DNS

### 7.1 做法

与 research-net §3.3 的建议 A 相同：

- 解析器监听 `198.18.0.1:53`（UDP 和 TCP）。Windows 的接口 DNS 不能指定端口，所以不能沿用 Linux 的 `127.0.0.1:1053`。发往本机地址的包走环回，不进隧道。
- 只在 cellglide0 上用 `SetInterfaceDnsSettings` 设一个 DNS 地址（`198.18.0.1`）。手机 DNS 关闭时设 `FALLBACK_DNS`，与 Linux 的 `DnsPlan::Servers` 相同。
- 我们的网卡跃点为 0，Windows 优先把查询发给我们。
- 停止时清空本网卡的 DNS 设置。卸载时删除 `Tcpip\Parameters\Interfaces\{我们的 GUID}`。
- 不用 NRPT，不碰其他网卡。

### 7.2 对 cg-core 的两处修改

1. **启动顺序。** 现在控制器先起解析器、再调用 `backend.start`。Windows 上 `198.18.0.1` 要等网卡建好才能绑定，所以顺序要变成：建网卡和地址 → 起解析器 → 把网卡 DNS 指向解析器 → 加路由。做法：`TunnelBackend` 增加一个默认实现为空的阶段钩子，Linux 后端行为不变；具体签名由实施计划定。不变的要求是：**网卡 DNS 指向解析器之前，解析器必须已经在监听**。
2. **应答期限。** Windows 的 DNS 客户端在首选服务器约 1 秒不回应时，会把查询发到所有网卡的服务器，这就是泄漏。`ControllerConfig` 增加 `resolver_deadline`：上游（经手机的 DoH）在期限内没回，先回 SERVFAIL，上游的结果晚到就丢掉。Linux 保持现在的 10 秒。Windows 的取值由 W0 实测确定（预计 800 ms 左右），同时实测 Windows 收到 SERVFAIL 后会不会再去问其他网卡。

### 7.3 严格 DNS

~~research-net 建议的「严格 DNS」开关**不在 1.0 的计划里**，除非 W0 实测证明 7.1 的做法会泄漏。~~

**2026-10-30 修订（W0 实测结果）**：7.1 的做法会泄漏。Windows 把每个查询发给 cellglide0 的同时（0.1 ms 内）并行发给 Wi‑Fi 的 DNS 服务器，我们立即应答或回 SERVFAIL 都挡不住（`docs/validation/windows-1.0-w0.md`「DNS」一节）。用户已授权开发者自行决定，因此改为：

- **连接期间默认启用严格 DNS**：服务打开一个 WFP 动态会话（`FWPM_SESSION_FLAG_DYNAMIC`），在 `ALE_AUTH_CONNECT` 的 v4 / v6 层拦截所有远端端口 53 的 UDP 和 TCP 出站，放行本地接口为 cellglide0 的流量和环回流量。断开时关闭会话；进程崩溃时内核自动删除全部规则，不留任何持久状态。
- 不改任何网卡的配置，但效果是系统级的：连接期间，其他 VPN 的分流 DNS、只认 53 端口的本地工具会失效。断开后恢复。界面以后在设置里加关闭开关（W2/W3）。
- 解析器期限取 2800 ms（实测值）。

## 8. cellglide.dll（cg-ffi）

### 8.1 边界

DLL 承担界面需要的一切非显示逻辑：

- 和服务通信：请求、订阅状态。
- 测速和 DNS 泄漏检测：在用户进程里跑，与 Linux 一样，不给服务加任何能力。
- 诊断：向服务要打包好的内容，给用户看，再由 DLL 上传或保存到文件。
- 视图模型：把服务的快照、测速进度、泄漏结果、连接记录变成界面直接绑定的结构，文字已经翻译好，颜色只给语义（正常、警告、错误）。
- 文案：界面上的固定文字（按钮、标题）也从 DLL 按键取，yml 仍是唯一来源。
- 用户偏好（测速「不再提示」、测速历史）：存在 `%LOCALAPPDATA%\CellGlide\`，读写由 DLL 负责。

C# 端只做：XAML 页面、绑定、托盘、窗口、自启动注册表、单实例。

### 8.2 C 接口

接口刻意做得很窄，消息都是 UTF-8 JSON，这样加功能时不用改 C 接口：

```c
typedef void (*cg_event_fn)(void *ctx, const uint8_t *json, size_t len);

int32_t  cg_init(const uint8_t *lang, size_t len, cg_event_fn on_event, void *ctx); // 起 tokio 运行时
uint64_t cg_send(const uint8_t *json, size_t len);  // 发一个命令，返回命令编号；结果以事件返回
void     cg_tr(const uint8_t *key, size_t key_len, const uint8_t *args_json, size_t args_len,
               uint8_t **out, size_t *out_len);    // 同步取一条文案
void     cg_free(uint8_t *ptr, size_t len);
void     cg_shutdown(void);
```

- 命令（`cg_ffi::api::Command`）：`Subscribe`、`Request(cg_ipc::Request)`、`SpeedStart { include_wifi, confirmed }`、`SpeedCancel`、`LeakStart`、`LeakCancel`、`DiagnosticsSend { … }`、`DiagnosticsSave { path, … }`、`SetLang`、`GetPrefs`、`SetPrefs`。
- 事件（`cg_ffi::api::Event`）：`Reply { id, result }`、`State(OverviewView)`、`SpeedProgress(SpeedView)`、`LeakProgress(LeakView)`、`ServiceGone` 等。
- 事件回调在 DLL 自己的线程上调用；C# 收到后转给 UI 线程的 `DispatcherQueue`。
- 每个导出函数都包在 `catch_unwind` 里，panic 变成错误事件，不跨 FFI 边界。
- 绑定用 csbindgen 在 `cg-ffi/build.rs` 里生成 `windows/CellGlide.Core/Native/NativeMethods.g.cs`，提交进仓库，CI 检查它与源码一致。

### 8.3 契约测试

`cg-ffi` 的 Rust 测试为每种命令和事件生成样例 JSON，写到 `crates/cg-ffi/tests/fixtures/`，提交进仓库。Rust 测试断言序列化结果与样例一致；C# 测试读同一批样例，断言能反序列化、再序列化后不变。任何一边改了字段，另一边的测试就会失败。

### 10.2 install.ps1

用法：`irm https://pkg.cellglide.com/install.ps1 | iex`。

1. 不是管理员时，把自己存到临时目录，用 `Start-Process -Verb RunAs` 提权重跑。
2. 检查系统：Windows 11；ARM64 要求 24H2 及以上（「Apple 设备」arm64 包的要求）。不满足就说明原因并退出。
3. 检查 Apple Mobile Device Service（注册表键 + 服务状态）。没有时说明原因，询问是否用 `winget install --id 9NP83LWLPZ9K --source msstore` 安装；协议由用户在 winget 里自己同意，脚本不加 `--accept-*`。用户拒绝也继续装 CellGlide，只是提示装好 Apple 设备之后才能用。
4. 按架构下载 zip 和 `SHA256SUMS`，`Get-FileHash` 校验，不一致就中止。`Invoke-WebRequest` 一律加 `-UseBasicParsing`。
5. 已安装旧版时：结束所有会话里的 `CellGlide.exe`，`Stop-Service CellGlide`，等 `cellglide0` 消失（最多 10 秒），再替换文件。
6. 解压到临时目录，整体复制到 `C:\Program Files\CellGlide\`。
7. 新建或更新服务（路径加引号），设置失败重启、sidtype、privs；建 `C:\ProgramData\CellGlide\` 并用 icacls 设显式 ACL。
8. 开始菜单快捷方式；在 `HKLM\…\Uninstall\CellGlide` 写卸载项，让它出现在「已安装的应用」里，卸载命令指向 `uninstall.ps1`。
9. 启动服务；以当前用户身份启动界面（提权进程用 `explorer.exe` 转启，避免界面以管理员身份运行）。
10. 运行 `cellglide doctor`，把结果打印出来。

### 10.3 卸载

`irm https://pkg.cellglide.com/uninstall.ps1 | iex`，或在「已安装的应用」里卸载，两者跑同一个脚本：结束界面 → 停服务 → 等网卡消失 → 删除服务 → 删除快捷方式、卸载项、每个用户的 Run 值、我们 GUID 的 Tcpip 接口键、`C:\Program Files\CellGlide\`。`C:\ProgramData\CellGlide\` 和 `%LOCALAPPDATA%\CellGlide\` 只在加 `-Purge` 时删除。不碰 Apple 设备。

### 10.4 没有签名带来的问题

- 脚本下载的文件不带网络标记，不会弹 SmartScreen。用户从浏览器手动下 zip 时会带上，README 说明用 `Unblock-File` 或改用一行命令安装。
- 开着「智能应用控制」的电脑会拦截未签名程序。安装脚本检测到它处于强制模式时，提前说明，并指向以后的签名版。
- 每个版本发布前把 exe 和 dll 提交到微软的误报申诉页面。

## 12. 测试策略

### 12.1 自动化

- **cg-netstack**：内存包设备 + 本地假 SOCKS5 服务器，覆盖 TCP 收发和半关闭、UDP ASSOCIATE、DNS over UDP 和 TCP、IPv6、超时回收、会话上限。Linux 上另跑一组对比测试：同样的流量分别经 hev 和 cg-netstack，结果一致。

- **cg-ipc / cg-service**：命名管道往返、订阅、服务端身份校验、按令牌授权（用可注入的身份做单元测试，再加一个连真管道的集成测试）。

## 13. 对 AGENTS.md 的修改

## 17. 风险

1. **DNS 泄漏**：Windows 的 DNS 客户端在超时或并行查询时可能问到其他网卡。缓解：§7.2 的应答期限；W0 用 pktmon 实测；严重时把严格 DNS 拿回来问用户。
2. **ARM64 没有实机**：Apple 的 ARM64 驱动来自 Windows Update，「Apple 设备」arm64 包要求 24H2。CI 只能验证编译、单元测试和 wintun，接 iPhone 要靠虚拟机或借机器。
3. **引擎差异**：ipstack 的吞吐、CPU 占用和 TCP 行为可能和 hev 不同。缓解：对比测试和实机测速。
4. **未签名**：智能应用控制会拦截，Defender 可能误报。
5. **「信任」提示**：AMDS 可能不会自己弹出，首次使用多一步。
6. **53 端口冲突**：ICS / Hyper-V 可能占用。doctor 给出明确原因。
7. **服务端**：诊断上传服务目前对 Windows 的 UA 返回 403，要改私有 CellProxy 仓库并部署；DNS 泄漏检测服务要确认接受 Windows 客户端。部署前先问用户。
8. **WinUI 3 自包含体积**：每个 zip 预计 60–120 MB，Native AOT 能减少一部分。
