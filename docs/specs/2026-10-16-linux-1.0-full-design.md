# CellGlide Linux 1.0 完整版设计

日期：2026-10-16
状态：待用户确认。
前置：`docs/specs/2026-10-15-linux-1.0-design.md`（以下称「1.0 设计」）、`docs/validation/linux-1.0.md`（M1、M2 实机结论）。Mac 参考实现在 CellProxy 仓库，下文写作 `CellProxy:路径`。

本文件修订 1.0 设计中 M3、M4 的范围，并替换其 §3.8「界面」。M1、M2 及 §3.1–3.7、§3.9–3.10 不变，除非下文另有说明。

## 1. 为什么改

M2 之后，Linux 版已经稳定可用：会自动连接、管理 DNS、以专用用户运行，也能从软件源安装和升级。但它「只是能用」：托盘只有连接、断开和退出，窗口里只有几行字，其他功能都没有。用户的原话是「现在的版本太简陋了」。

这一版要让 Linux 用户拿到一个像样的产品：功能上大体对齐 Mac 1.0.0，界面参考 Mac，但不要求逐项一致。

## 2. 用户已定事项

- 面向普通 Linux 用户，正式发布。
- 必须做：托盘面板、手机卡片、测速、DNS 泄漏测试、连接历史、诊断、设置。
- 界面参考 Mac 1.0.0（`CellProxy:Desktop/macOS/CellProxyMac/App/MainWindow.swift` 与 `App/Pages/`）。
- 一并带上 beta.2 实机测试时提出的两项：Dock 图标与窗口对应（`application_id`），以及在界面里显示版本号。这两项已在本地提交 53b2f22，尚未审查、未发布。
- 分流和流量去向地图这一版不做，以后做不做未定。西班牙语这一版也不做。
- 全部做完、测完后一次发布为 Linux 1.0.0 正式版，中间不再给用户发 beta。

## 3. 目标、非目标与反目标

**目标**
- 用户打开 CellGlide，看到的是一个完整的应用：带侧边栏的主窗口、信息丰富的手机卡片，以及能自查、能报问题的工具。
- 每项功能在 Linux 上真实可用，在六个支持的发行版上测过。

**非目标**
- 分流、规则集、流量去向地图、西班牙语。
- Mac 独有的问题：「移到应用程序文件夹」、旧版 DNS 残留清理、后台运行授权卡片。
- 应用内自动更新。更新继续走 apt / dnf。

**反目标**（技术上能用也算失败）
- 为了界面功能而放宽服务的权限边界。服务仍只有 CAP_NET_ADMIN；界面仍是普通用户进程。
- 测速或 DNS 泄漏测试改动系统网络设置，或在用户不知情时消耗大量流量。
- 读不到的数据显示成假的或 0。读不到就不显示这一项。
- 诊断在用户没看过内容、没确认的情况下就发送出去。

## 4. 设计

### 4.1 主窗口

照 Mac 的侧边栏结构，去掉这一版不做的页面：

| 分区 | 页面 |
|---|---|
| （无标题） | 概览 |
| 工具 | 测速、DNS 泄漏测试 |
| 活动 | 连接历史、诊断 |
| 应用 | 设置、关于 |

- 侧边栏的提醒标记照 `CellProxy:Sources/DesktopCore/MainSectionBadge.swift`。例如连接历史里有未处理的中断时显示橙点或红点。
- 每页的布局、分组和文案以 Mac 对应页面为蓝本，「Mac」改为「电脑 / computer」。控件以 iced 能做到的为准，不追求像素一致。
- 窗口底部显示版本号（已在 53b2f22 实现）。
- 窗口的 `application_id` 为 `cellglide`，两个桌面文件都带 `StartupWMClass=cellglide`（已在 53b2f22 实现）。实机要验证 GNOME Dock 显示的是 CellGlide 图标。

### 4.2 托盘面板

Linux 托盘（StatusNotifierItem）只支持菜单，没有 Mac 那种弹出面板。做法：

- **左键点托盘图标**：打开一个紧凑的面板窗口，内容对应 Mac 菜单栏面板（`CellProxy:App/PanelView.swift`，去掉分流开关）：状态、连接 / 断开、简版手机卡片、健康提示、「打开 CellGlide」。面板失去焦点时自动关闭。
- **右键菜单**：版本、连接 / 断开、打开 CellGlide、退出。
- **图标状态**：照 Mac，正在走手机网络时用另一个图标，有健康问题时加橙点。
- Wayland 下应用不能自己决定窗口位置，面板出现在哪里交给桌面环境决定，这一点可以接受。

### 4.3 手机卡片

照 `CellProxy:App/PhoneCard.swift`、`PhoneMetricsFeed.swift`、`PhoneBattery.swift`，显示：

- 运营商（含副品牌）与网络制式（如 5G NSA）
- 实时下行 / 上行速度，带 1 分钟走势
- 连接质量等级、延迟、丢包
- 本次连接用量
- 电量、是否充电、充电功率；温度与电池健康能读到才显示
- 发热提醒

数据来源：
- 运营商、制式、速度、质量等手机指标来自 iPhone 端回传，Linux 已在接收（`cg-core` 用其中的 `exit_ok`），只需把其余字段显示出来。
- 电池细节在 Mac 上由电脑经 USB 读取（`CellProxy:Sources/DesktopCore/PhoneBattery.swift`），再经 8091 端口报给手机，供手机显示充电功率（`CellProxy:Sources/SharedControl/PhoneBatteryReport.swift`）。Linux 上能经 usbmuxd / lockdownd 读到多少，由实现时实测确定（见 §6）。读得到的，同样照 Mac 报给手机。
- **iPhone 端协议不改**（沿用 1.0 设计）。Linux 读不到的项就不显示、不占位，不为此改 iOS。

概览页放完整卡片，托盘面板放简版。

### 4.4 测速

照 `CellProxy:App/SpeedTestPage.swift`、`SpeedTestController.swift` 与 `CellProxy:Sources/SharedSpeed`：

- 测手机网络；可选同时测 Wi‑Fi 或有线网络做对比，给出结论。
- 实时曲线，历史记录，可清空。
- 开始前提示一次测速可能消耗约 1.3 GB，可选「不再提示」。
- 测速服务器、时长、算法与 Mac 相同，保证两边结果可比。
- 对比测 Wi‑Fi 时，只让测速流量走 Wi‑Fi，不改系统路由、不断开手机连接。

### 4.5 DNS 泄漏测试

照 `CellProxy:App/DNSLeakPage.swift` 与 `DNSLeakTest.swift`：解析 20 个随机域名，按网络分组列出实际用到的解析服务器，标出 ECS，给出结论（已加密 / 运营商 DNS / 泄漏 / 未共享 / 未检测到）。

Linux 比 Mac 多一种状态：DNS 未由 CellGlide 接管（`DnsMode::Unmanaged`）。这时结论页要说明原因，并给出 `cellglide doctor` 的修复提示。

### 4.6 连接历史

即 1.0 设计 §3.6，界面照 `CellProxy:App/Pages/HistoryPage.swift`：

- 24 小时色条
- 当天事件
- 每次中断的原因与当时的数据（线缆与手机延迟、丢包、网络制式、失败次数、发热）
- 可前后翻看 7 天

### 4.7 诊断

即 1.0 设计 §3.7，界面照 `CellProxy:App/Pages/DiagnosticsPage.swift`：

- 选择范围（24 小时或 7 天）
- 填写邮箱与备注（可选）
- 「查看将发送的内容」
- 发送后显示报告编号
- 也可以只保存到文件

### 4.8 设置

照 `CellProxy:App/Pages/SettingsPage.swift`，去掉 Mac 独有项：

- 自动连接（开 / 关）
- 使用哪台 iPhone（自动，或一台记住的手机；列表显示名称与型号）
- 登录后在后台启动（即 1.0 设计 §3.8 的「登录后显示托盘」）
- 插上 iPhone 时打开窗口。界面在后台运行时，检测到手机插上就打开窗口；界面没在运行时不做，Linux 上没有可靠的办法在用户会话里拉起界面。
- 手动代理地址（SOCKS5）与复制按钮
- DNS 状态与 `doctor` 检查结果的入口

现在只能用 `cellglide settings` 改的项，都要能在这里改。

### 4.9 关于

照 Mac：版本、Telegram 链接、计费说明、开源许可。

## 6. 交给实现者决定的事

以下由实现者决定，在实施计划或执行记录里写明即可，不必回来问用户：

- 电池信息在 Linux 上的读取方式（usbmuxd / lockdownd），以实测为准，拿不到的项按 §3 反目标处理。
- 测速和 DNS 泄漏测试放在服务端还是界面进程里跑。约束是不能因此给界面进程加权限。
- 控制协议的具体扩展（新请求、事件推送、版本号升到几）。同一安装包内各程序版本总是一致，不需要兼容旧协议。
- iced 下各页的具体控件、曲线画法与面板窗口的实现方式。
- Mac 文案中各句的 Linux 改写。

## 6.1 已替用户定下的事（实现者照此执行）

- **桌面环境**：GNOME（Ubuntu 默认）必须在测试机实机通过。KDE Plasma 在虚拟机里验证托盘、面板与窗口（不接手机，用假服务或未连接状态），不要求接手机实测。
- **测速的流量**：自动化测试用假后端或小数据量；接手机的完整测速在整个开发过程中控制在少数几次（每次约 1.3 GB），记录在验证文档里。
- **服务端**：诊断上传服务（`CellProxy:Diagnostics/worker`）需加入 Linux；DNS 泄漏测试用的 `leakcheck.cellglide.com` 需确认接受 Linux 客户端。部署方式见用户答复（§8）。

## 7. 风险

1. 手机卡片的数据量取决于 Linux 上能拿到什么。最坏情况下电池细节只剩电量，卡片会比 Mac 简单。
2. 托盘面板在不同桌面环境（GNOME、KDE）上的表现不同，Wayland 下位置不可控，要在两种桌面上都实测。
3. 测速对比 Wi‑Fi 需要让一部分流量绕开 cellglide0，实现时要避免影响其他网卡和其他 VPN（`AGENTS.md`）。
4. 诊断上传依赖 CellProxy 仓库里的服务端改动（1.0 设计 §3.7），需要部署。
5. 工作量比原 M3 / M4 大约多一倍，正式版时间相应推后。

## 8. 用户答复

- **服务端部署**（2026-10-16）：用户授权直接修改并部署，不需要交回给用户。
  - 诊断上传服务（`CellProxy:Diagnostics/worker`）用 wrangler 部署到正式环境。
  - DNS 泄漏检测服务在 专用 VPS 上，见 `CellProxy:Docs/DNSLeak-VPS.md`，可以直接 SSH 修改。
  - 粗看 `CellProxy:Scripts/dnsleak-server.py`，它不按平台过滤，Linux 客户端很可能无需改动；M3 实测确认。
  - 改动服务端时只改与 Linux 有关的部分，改完确认 Mac 与 iOS 的现有功能不受影响。
