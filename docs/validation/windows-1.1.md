## 睡眠和唤醒（没插线）

- 原来：睡眠时结束无线会话，唤醒后不重开，用户每次合盖都要手动再连。
- 改为：唤醒 3 秒后自动重新开始无线连接，正显示验证码时除外；睡眠到唤醒之间点了「取消」「断开」或关了开关，也不重开（提交 f243de0）。
- 真机：唤醒后约 24 秒回到无线；2026-11-23 另一轮，唤醒 3 秒后开始，iPhone 25 秒后加入并连上。

## 插线切换

问题：插线后 iOS 很久才显示 USB；拔线后回不到无线。原因是接入点关掉再开后，iPhone 不会自己重新加入（2026-11-19 拔线后 5 分钟没回来，附近没有别的已保存网络也一样）。

| 改动 | 提交 |
|---|---|
| 已连上的无线会话被插线接管时「挂起」：先撤无线隧道（iPhone 立刻知道连接断了），接入点保持开着；拔线后挂起的会话直接重连 | 309f873 |
| 插线期间电脑睡眠：接入点照样关；唤醒时那台 iPhone 还插着，3 秒后重新打开接入点并继续挂起 | e25eafb |
| 每次 USB 会话把接入点的名字和密码交给 iPhone（`hotspot-v1`，iOS 定义），拔线时由 iOS App 请求加入 | 2fa13d6 |

真机（时间为 UTC）：

| 情形 | 结果 |
|---|---|
| 2026-11-19，插线、拔线，期间没睡眠 | 插线 0.6 秒转到 USB；拔线 11 秒回到无线 |
| 2026-11-19，插线期间闲置睡眠，唤醒后拔线（没有 `hotspot-v1`） | 唤醒后接入点重开，但 iPhone 没加入，Wi‑Fi 列表里能看到、不会自动连；5 分钟后放弃 |
| 2026-11-23，`hotspot-v1`，插线、睡眠、唤醒、拔线 | 18:50:35 接入点重开，18:50:42 iPhone 还插着线就加入了；18:50:43 拔线，18:50:48 回到无线（5.5 秒） |
| 同上，另一轮 | 睡眠时关接入点的操作被系统冻住，唤醒后 18:48:17 才完成，新的接入点要等它；拔线后 23.5 秒回到无线（接入点打开后 iPhone 3.5 秒加入）。只出现一次，没有修 |
| 2026-11-23，附近有已保存的 Wi‑Fi，同样的步骤 | 拔线后 1.5 秒 iPhone 加入，6 秒回到无线 |

- 用户反馈：无线连接和插线两种方式都能回来。前几轮测试时 iPhone 上其它已保存的 Wi‑Fi 都删掉了；最后一轮重新加入了常用 Wi‑Fi，也回来了。
- iOS 端的实验（见 `docs/specs/2026-11-19-ios-auto-join-request.md` 附的协议说明）：手机不在接入点上时，App 每次请求加入都会弹系统确认框；手机连着别的已知 Wi‑Fi 时系统不会自己换过来。所以能做到的是「点一下」，不是「什么都不按」。
- 第一次加入时 iPhone 等了 44 秒（18:56:40 开接入点，18:57:24 加入），可能是用户在确认框里点的；待用户补充。

## 网络快照

- 2026-11-19 安装前和唤醒后对比：只有 Wi‑Fi 网卡的 `Tcpip\Parameters\Interfaces\{f870e3e0…}\DhcpGatewayHardware` 变了（路由器 MAC 的最后一个字节 d→e）。这是 Windows 自己在 DHCP 续租时写的，不是 CellGlide 改的，比较脚本不改。
- 最终对比（2026-11-23，全部测完、断开、接入点关掉之后，对比 2026-11-17 安装前的快照）：除了上面那个 `DhcpGatewayHardware`，只有 Tailscale 的 IPv6 MTU 从 1420 变成 1280。不是 CellGlide 改的：CellGlide 只在 GUID 是 cellglide0 的网卡上写 MTU（`cg-platform/src/windows/ip.rs` 的 `check_luid`），写的是 1500；1280 是 Tailscale 自己的 MTU，它的 IPv4 一直是 1280。2026-11-19 的几次快照里还是 1420，11-23 连续运行前已经是 1280，推断是 Tailscale 自己重新设的。

## 待办

- §10 第 2 项的移除和取消、第 3、4、8 项：2026-11-23 用户决定不再测，验收到此结束。
- 计划里另加的：停掉 Apple Mobile Device Service 时无线仍可用；每一步前后和会话中的快照。
- 一开始就插线用 USB（之前没连无线）时，拔线后 iPhone 会不会弹「无法加入网络」：电脑这时不开接入点。要不要改由 iOS 判断，待定。
