# Linux 1.0 · M3 数据与服务 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 服务端补齐完整的手机卡片数据（含经 USB 读取的电池并回报给手机）、健康判定与 7 天连接记录、诊断打包；新建用户进程共用的 `cg-tools`（测速、DNS 泄漏测试）与上传用的 `cg-diag`；控制协议升到 4；CLI 能看历史、导出与发送诊断、测速、测 DNS 泄漏、显示完整手机卡片。

**Architecture:** 服务（`cellglide-service`，只有 CAP_NET_ADMIN）负责一切依赖手机会话与系统日志的数据：手机指标与电池（`cg-core::phone_feed`、`cg-core::lockdown`、`cg-core::battery`）、健康判定与 JSONL 记录（`cg-core::health`）、诊断打包（`cg-service::diagnostics`，用 `cg-diag` 的数据结构与脱敏）。测速与 DNS 泄漏测试在用户进程里跑（`cg-tools`），只读服务的 Snapshot；Wi‑Fi / 有线对比用 SO_BINDTODEVICE 把套接字绑到物理网卡，不改路由。共享的线上类型都在 `cg-ipc`，`PROTOCOL_VERSION = 4`。

**Tech Stack:** 在 M2 之上新增 jiff 0.2（时区与本地日期）、fancy-regex 0.19（脱敏正则需要环视）、socket2 0.6（`features = ["all"]`，`bind_device`）；HTTPS 继续用 rustls 0.23 + tokio-rustls 0.26 + webpki-roots，HTTP 客户端用工作区已有的 hyper 1 / hyper-util；Node `node --test` 与 wrangler（CellProxy 仓库的诊断服务）。

**Spec:** `docs/specs/2026-10-16-linux-1.0-full-design.md`（§3 反目标、§4.3–4.7 的数据部分、§5 M3 行、§6、§6.1、§8），它修订的 `docs/specs/2026-10-15-linux-1.0-design.md`（§3.4 的记录项、§3.6、§3.7、§5）。验证记录：`docs/validation/linux-1.0.md`。

**计划层面的决定（spec 细化，执行者照此做）：**
1. **手机卡片数据放进 `Snapshot`，不另设请求。** 界面本来就订阅 Snapshot；手机帧每秒一帧、电池每 10 秒一次，放进 Snapshot 就随推送到达，另设请求则要么轮询、要么再开一条订阅。数据是会话状态的一部分，同包内版本一致，改形状不需要兼容。`Snapshot.metrics: Option<MetricsSummary>` 删除，换成 `phone: Option<PhoneCard>`；另加 `health: HealthStatus` 与 `labels`（每部手机的名称与型号）。
2. **连接记录、诊断用独立请求**：`history { day }`、`diagnostics { range, contact }`。诊断包以 JSON 文本 `json: String` 返回：用户预览的、保存的、上传的是同一串字节。客户端读回复的上限改为 4 MiB（`MAX_REPLY_LINE`）；服务读请求仍是 64 KiB（`MAX_LINE`）。
3. **测速的手机线路绑定 `cellglide0`（SO_BINDTODEVICE），不用 Mac 的 SOCKS 检查转发器。** 用户进程不知道服务里转发器的端口，也不该扩大对它的使用；绑定 `cellglide0` 测的正是电脑流量实际经过的路径。Wi‑Fi / 有线线路绑定「`/proc/net/route` 里 metric 最小、不是 `cellglide0` 的 IPv4 默认路由」所在网卡。Linux 5.7 起非特权进程可对未绑定的套接字设置 SO_BINDTODEVICE（内核提交 c427bfec18f2 “net: core: enable SO_BINDTODEVICE for non-root users”；man 7 socket 未写此限制变化，以提交与 Task 13 的 Lima 实测为准）；六个支持的发行版内核都 ≥ 5.15。
4. **连接记录的 JSON 与 Mac 同形**：字段 `t`、`kind`、`cause`、`phase`、`duration`、`detail`、`snapshot`，`kind` / `cause` / 快照键沿用 Mac 的 camelCase（`tunnelStarted`、`phoneExit`…）。1.0 设计 §3.6 列出的 Linux 新增种类按同一风格写作 `bypassUnavailable`、`bypassUpdateFailed`、`dnsNotAuthorized`，另加 `serviceStarted`（服务启动，便于看出崩溃重启）。原因 `macRelay` 在 Linux 写作 `computerRelay`（1.0 设计 §3.6）；快照的 `macVersion` 改为 `computerVersion`，去掉 `helperPID`。时间 `t` 取整到秒，RFC 3339 UTC（`2026-10-08T19:00:00Z`），与 Mac 的 `.iso8601` 一致。
5. **电池读取只在会话期间运行**（Mac 在面板可见或手机 App 在前台时读）。服务看不到界面是否可见；会话期间手机 App 一定在共享，回报 8091 也只有这时有人收。名称与型号（不需要会话）在每次插上时读一次。
6. **包内服务单元补上 `SupplementaryGroups=systemd-journal`。** 1.0 设计 §3.5 与 M2 计划都写了，但 `packaging/cellglide.service` 里没有；没有它，以 `cellglide` 身份运行的 `journalctl -u cellglide` 读不到系统日志。只增加读日志的组，不增加能力位，符合反目标。
7. 新文案全部进 `crates/cg-i18n/locales/{zh-CN,en}.yml` 与 `KEYS`；中文取 Mac 的 zh 原句（即 `Localizable.strings` 的键），英文取 `CellProxy:Sources/SharedLocalization/Resources/en.lproj/Localizable.strings` 中同一键的译文，「Mac」改为「电脑 / computer」。本计划按「键 → Mac 中文原句」列出，英文照该文件查。Mac 原句里讲分流（Linux 不做）的半句删去。

## Global Constraints

- `AGENTS.md` 全部适用：只动 `cellglide0` 的 DNS 与 realm 198 路由；测速、DNS 泄漏测试不改任何路由、DNS 或网卡设置；安装与测试前后网络快照一致。
- iPhone 端协议不改：只读 8088 / 8089 / 8090 与 lockdown（62078），只向 8091 写 `CellGlide-battery` 帧（格式同 `CellProxy:Sources/SharedControl/PhoneBatteryReport.swift`）。
- 读不到的数据是 `None` 并且不显示，绝不填 0 或假值（spec §3 反目标）。
- 服务权限不变：仍只有 CAP_NET_ADMIN；测速与 DNS 泄漏测试只在用户进程（`cg-tools`）里跑。
- 诊断只在用户明确确认后上传；CLI 先打印全部内容再要求输入 `y`，`--yes` 跳过确认。
- `PROTOCOL_VERSION = 4`（本里程碑只升一次，所有新请求、新字段都在 4 里）。
- 诊断包：`format: 1`、`platform: "linux"`，上限 1 000 000 字节、日志 2000 行、单行 2000 字符、环境值 2000 字符、备注 2000 字符、邮箱 200 字符；User-Agent `CellGlide-Linux/<CARGO_PKG_VERSION>`；端点 `https://diag.cellglide.com/v1/reports`。
- 连接记录：`/var/lib/cellglide/health/YYYY-MM-DD.jsonl`（服务所在时区的本地日期），只追加，保留 7 天。
- 测速：服务器 `speed.cloudflare.com:443`，6 条流、每个方向 10 秒、前 2 秒预热不计、下载上限 1 000 000 000 字节、上传上限 300 000 000 字节、每次请求最多 90 000 000 字节、每 0.5 秒采样、延迟取 3 次 `GET /__down?bytes=0` 的中位数；相差 20% 以内为「相近」。
- DNS 泄漏：20 个名字 `<16 位小写十六进制>-<n>.leak.cellglide.com`，每个解析最多等 6 秒，结果取 `https://leakcheck.cellglide.com/v1/<token>`（超时 15 秒）。
- 用户可见文字只在 `cg-i18n` 的 yml 里；线上类型只在 `cg-ipc`。
- 依赖：`jiff = { version = "0.2", features = ["serde"] }`、`fancy-regex = "0.19"`、`socket2 = { version = "0.6", features = ["all"] }`，加到 `[workspace.dependencies]` 后各 crate 用 `.workspace = true`。PEM 解析用 `rustls::pki_types::pem::PemObject`（不用已停止维护的 rustls-pemfile）。
- 每个代码任务结束前：macOS 上 `cargo fmt --all`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 通过；Linux 专有代码另跑 `scripts/linux-test.sh`（Docker）；需要特权的只在 Lima `cellglide-test`（仓库只读挂载，`CARGO_TARGET_DIR=$HOME/cg-target`）或一次性 Lima VM 里跑。不在 Mac 上运行特权代码。
- **标有「控制者」的步骤由控制者（或用户）在测试机 `root@<test-machine>` 上做**，执行者写好命令后停下，等控制者回填结果。接手机的完整测速整个开发过程只做少数几次，由控制者决定，不在自动步骤里。
- 分支：`linux-1.0-full`，从 `linux-1.0` HEAD（53b2f22 之后的最新提交）切出。提交信息末尾加 `Co-Authored-By:`，署名写实际完成提交的模型。

## Review Focus

1. **两个手机来回插拔、拔线时正在读电池或 lockdown 会话**：读到一半的 TLS 会话、diagnostics relay 连接与 8091 报告连接都要随会话结束而关掉，不得卡住状态机或泄漏任务；下次连接重新开始。测试放在 Task 5（`battery_tasks_stop_with_the_session`）。
2. **服务时区与日期边界**：在 23:59 写入、跨午夜读取，或系统时区在两次运行之间改变（笔记本出差），`history` 要读到正确的当天条目与「零点时状态」。测试放在 Task 6（`reads_events_written_in_another_time_zone`、`day_start_replays_previous_days`）。
3. **记录目录不可写或磁盘满**：写记录失败只记一条日志，不影响连接、不 panic，`history` 返回已有内容。测试放在 Task 7（`unwritable_log_dir_keeps_connection_working`）。
4. **Wi‑Fi / 有线对比时没有可用的物理默认路由**（只连着手机、或另一个 VPN 占了默认路由）：对比部分给出「找不到网卡」的原因并跳过，手机线路照常测，绝不回退为不绑定的套接字（那会测到手机线路）。测试放在 Task 12（`missing_uplink_fails_without_falling_back`）。
5. **诊断里出现 Linux 特有的个人信息**：`/home/<用户名>`、主机名在 journald 行首（`Oct 16 12:00:00 alice-thinkpad cellglide-service[123]:`）、systemd 单元与 `.service` 路径；主机名必须被替换，系统路径与单元名保留可读。测试放在 Task 8（`linux_journal_line_hides_host_keeps_unit`）。

`cg-core/src/lockdown.rs` 按 `CellProxy:Sources/DesktopCore/PhoneDiagnostics.swift` 的 `openRelay` 顺序：连 62078 → `StartSession { Label: "CellGlide", HostID, SystemBUID }` → 有 `EnableSessionSSL: true` 则在同一条流上做 TLS → `GetValue` `ProductType`、`ProductVersion`、`BasebandVersion`、`SIMTrayStatus`、`CarrierBundleInfoArray`（只取 `CFBundleIdentifier`、`MCC`、`MNC`，其他字段丢弃）→ `StartService com.apple.mobile.diagnostics_relay` → `StopSession` → 连 relay 端口，`EnableServiceSSL: true` 则 TLS → `IORegistry { EntryName: AppleSmartBattery }`，回复 `Status == "Success"` 时取 `Diagnostics.IORegistry` 交给 `battery::reading_from_registry`。每个请求的读写都加 5 秒超时（`mux::REQUEST_TIMEOUT`）。

TLS：`rustls::ClientConfig::builder_with_provider(ring)`，允许 TLS 1.2 与 1.3，`with_client_auth_cert(vec![pairing.cert], pairing.key)`；服务端证书来自配对而非 CA，用一个只校验握手签名、不校验证书链的 `ServerCertVerifier`（`verify_tls12_signature` / `verify_tls13_signature` 交给 provider 的默认算法），`enable_sni = false`，`ServerName` 用固定的 `"lockdown"`。读写通道用 `enum Channel { Plain(MuxStream), Tls(Box<TlsStream<MuxStream>>) }`，`send(&Dictionary)` / `receive() -> Dictionary` 用 `cg_protocol::lockdown` 编解码。日志里不打印手机名称。

`FakeLockdown` 在 `FakePhone::start` 里绑 62078 与一个 relay 端口并 `mux.route` 过去；`session_tls` 时用 `device-cert.pem` / `device-key.pem` 起 rustls 服务端、`WebPkiClientVerifier` 以 `host-cert.pem` 为根要求客户端证书。

try:

except PermissionError:
