# Windows 1.0 · W3 WinUI 3 界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 WinUI 3 界面 `CellGlide.exe`（新工程 `windows/CellGlide.App`）：七个页面、托盘与面板、设置、关于、单实例、登录自启、图标、中英文，全部经 W2 的 `cellglide_native.dll` 和 CellGlide.Core 显示与操作，实机清单的界面部分在这台机器上连 iPhone 通过。

**Architecture:** App 只放 XAML、绑定、托盘、窗口和 Win32 胶水；凡是能脱离 WinUI 测试的界面状态（启动参数、单实例的去留、退出顺序、自启动注册表读写、插上 iPhone 时怎么开窗口、面板位置、托盘图标文件、把 0–1 坐标换成像素）放进 CellGlide.Core 的新命名空间 `CellGlide.Core.Desktop`，由 CellGlide.Tests 测。文字和判断仍全部来自 DLL：W3 只给 DLL 补几样界面要用、却还没有的东西（窗口标题、关于页数据、几个新键），并收掉 W2 留给 W3 的订阅健壮性与文案问题。

**Tech Stack:** .NET SDK 10.0.403（`windows/global.json` 固定）、C# `net10.0-windows10.0.26100.0`、Windows App SDK（自包含、不打包）、WinUI 3、H.NotifyIcon.WinUI、CommunityToolkit.Mvvm 8.4.2、System.Text.Json 源生成、xUnit v3（MTP）。Native AOT 优先，退路见 §9.1。Rust 1.99（cg-ipc、cg-ffi、cg-tools、cg-service 的小改）。PowerShell 5.1 + System.Drawing（生成 `.ico`）。

**Spec:** `docs/specs/2026-10-29-windows-1.0-design.md`（§8.1、§9 全部、§7.3 的界面开关、§14 的 W3 行；出口「实机清单的界面部分通过」）。页面结构、托盘面板和各页内容以 `docs/specs/2026-10-16-linux-1.0-full-design.md` §4.1–4.9 为准，实际显示什么以 `crates/cg-gui/src/{app,panel,tray}.rs`、`pages/*.rs`、`widgets/*.rs` 为准（不读 Mac 源码）。前置阅读：`docs/superpowers/plans/2026-10-30-windows-1.0-w2.md`（W2 已定的名字、契约规则）、`docs/validation/windows-1.0.md`（W1、W2 实机记录）、`AGENTS.md`。

**计划层面的决定（细化 spec，执行者照此做）：**
1. **App 与 Core 的分工**：WinUI 和 Win32 调用只在 `windows/CellGlide.App`；不碰 WinUI 的界面状态放 `windows/CellGlide.Core/Desktop/`（命名空间 `CellGlide.Core.Desktop`），注册表的真实读写也放这里（类上标 `[SupportedOSPlatform("windows")]`）。CellGlide.Tests 不引用 App。执行者裁定：测试进程加载不了 WinUI，这样能测的都测到，App 保持很薄。
2. **AOT 的取舍在 Task 1 定**：`PublishAot=true` 写进 App 的 csproj（锁文件才会记下 ILCompiler 包），Task 1 用 AOT 发布并启动一次；若有挡路的问题（AOT 下崩溃、托盘或 XAML 不工作，或第三方包报 IL2xxx/IL3xxx 警告而 `TreatWarningsAsErrors` 让发布失败），退回 `SelfContained=true` + `PublishReadyToRun=true`，并在验证文档写明原因。**不**用 `NoWarn` 压第三方的 AOT 警告。
3. **XAML 只用 `x:Bind`**（编译期绑定），不用 `{Binding}`。固定文字一律 `{x:Bind h:L.T('键')}`（`CellGlide.App.Hosting.L.T` 转调 `EventHub.Tr`）；动态文字绑定视图字段。执行者裁定：`{Binding}` 靠反射，AOT 下要另加元数据；`x:Bind` 不需要。
4. **语言在启动时定，运行中不切换**：`NativeCore.Start("")`（空 = DLL 的检测：`CELLGLIDE_LANG` 优先，否则 Windows 显示语言），不发 `SetLang`。执行者裁定：Windows 改显示语言要注销，界面跟着重启即可。
5. **窗口标题和关于页数据由 DLL 给**：`ChromeView` 加 `window_title`；新命令 `GetAbout` 回 `ReplyValue::About { version, telegram_url, licenses }`。`licenses` 是 DLL 内嵌的 `crates/cg-gui/assets/third-party-licenses.txt`（Rust 部分，去掉首行）加 `packaging/licenses/nuget.txt`（NuGet 部分）。执行者裁定：spec §2「C# 不重复写 Rust 已有的逻辑或文案」；Windows 专用、去掉 hev 等 Linux 项的 `THIRD-PARTY-LICENSES.txt` 是 W4 打包的事，届时改这一处来源即可。
6. **订阅静默探测放在 `cg_ipc::client::watch`**（Linux 托盘共用）：订阅开始后 `SILENCE`（30 s）没有新快照，就另开一个连接发 `Status`（期限 `TIMEOUT` 10 s）：超时或出错 → `Down(Timeout)`，按 `retry` 重来；回来的快照与订阅里最后一个不同 → 丢掉这个订阅，静默重新订阅；相同 → 继续等。执行者裁定：服务只在变化时推快照，安静本身不是故障，只有探测能区分「没变化」和「卡住了」。
7. **持续 panic 只报一次**：同一订阅里，`Fault` 只在 panic 信息与上一次不同时发，`ServiceGone` 只在原因变化时发（沿用 `ServiceDown::same_reason`）；之后一旦成功送出一个 `State`，记忆清空，再 panic 照常报。重试间隔不变。
8. **界面验收用小测速**：App 启动时读环境变量 `CELLGLIDE_SPEED_CAPS`，值为 `small` 时给 `SpeedViewModel.Caps` 设 `{ download_bytes: 10000000, upload_bytes: 5000000, seconds: 5 }`，其他值忽略；界面上没有任何入口。执行者裁定：出口要求测速页走一遍，而完整测速一次约 1.3 GB，W3 预算 200 MB。
9. **关窗口 = 隐藏**，程序留在托盘；退出只走托盘菜单、面板和关于页的「退出」（与 Linux 相同）。退出顺序：有测速或泄漏检测在跑先发取消（最多等 2 s 回复）→ 释放 `EventHub` → `NativeCore.Dispose()`（`cg_shutdown`）→ 去掉托盘图标 → `Application.Exit()`。
10. **托盘图标 GUID 按 exe 路径派生**（`TrayIdentity.GuidFor`）。执行者裁定：Windows 把通知区图标的 GUID 绑定到 exe 路径，换路径（开发目录与安装目录）用同一 GUID 会注册失败；按路径派生，同一安装位置的「在任务栏上显示」偏好也能保留。
11. **托盘图标按任务栏明暗选两套**（浅色任务栏用深色图形，深色任务栏用白色图形），读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\SystemUsesLightTheme`，`UISettings.ColorValuesChanged` 时重读。图标由 `scripts/gen-windows-icons.ps1` 用 System.Drawing 按托盘 SVG 的几何重画生成（这台机器没有 Python 和 ImageMagick），产物提交进仓库。
12. **自启动被系统禁用时**（`StartupApproved\Run\CellGlide` 首字节最低位为 1）：开关显示为关、不可操作，下面一行 `settings.launch_disabled_by_system`；我们从不写 `StartupApproved`。执行者裁定：spec §9.4「不覆盖」；首字节 `0x02`/`0x06` 为启用、`0x03`/`0x07` 为禁用，按最低位判断覆盖两种写法。
13. **诊断发送在 W3 可能被服务端拒绝**（spec §17 风险 7：诊断服务对 Windows UA 返回 403，部署是 W4 的事且须先问用户）。界面照常显示 DLL 给的错误句子；验收记录实际结果，不改服务端。若服务端已接受，记下报告编号交给用户决定是否删除。
14. **W3 不改 `.github/workflows/`**（Task 15 仍在等令牌的 `workflow` 权限）。W3 的 CI 增项进 `scripts/check-windows-core.ps1`，并列在文末「交给 Task 15 的 CI 增项」。

## Review Focus

1. **App 开着时服务停止、重启或从来没运行**：窗口标题、侧栏、面板、托盘图标和菜单都换成 `ServiceGone` 带来的 chrome（普通图标、菜单项「连接」、面板显示原因），概览不再显示旧的手机卡片，发出的命令在 `Error` 里给一句话；服务回来后自动恢复，不用重开 App。测试：Task 5 `Chrome_follows_state_and_service_gone`、`Tray_icon_follows_service_gone_chrome`；Task 2 `a_hung_service_after_the_first_snapshot_is_down`。
2. **第二次启动**（托盘已在运行时从开始菜单再点、登录自启时界面已开着、`--tray` 启动后又手动打开）：始终只有一个进程；手动启动把已有窗口带到前面；`--tray` 的第二次启动什么都不做就退出。测试：Task 4 `Launch_decision_matches_linux`、`Launch_options_read_tray_and_small_caps`。
3. **托盘图标在溢出区、任务栏在顶部或左侧、副显示器在主显示器左边（负坐标）、缩放 150%**：面板完整落在图标所在显示器的工作区内，取不到图标位置时贴工作区右下角。测试：Task 5 `Panel_sits_above_a_bottom_taskbar_icon`、`Panel_is_clamped_inside_the_work_area`、`Panel_without_an_icon_goes_to_the_corner`、`Panel_on_a_left_monitor_with_negative_coordinates`、`Panel_taller_than_the_work_area_starts_at_the_top`。
4. **测速或泄漏检测进行中退出**（托盘「退出」、关于页「退出」）：先发取消，DLL 正常关闭，之后没有任何回调；DLL 一直不回复时也在约 2 秒后照样退出。测试：Task 4 `Quit_cancels_running_tests_then_shuts_down`、`Quit_finishes_when_no_reply_comes`、`Quit_twice_is_one_quit`。
5. **自启动的注册表值被系统禁用、指向旧位置、或路径含空格**：禁用时开关为关且不可操作并说明原因；指向别处时显示为关，打开即改写为当前路径；命令行总是带引号的完整路径加 `--tray`；关掉只删我们自己的值。测试：Task 4 `Autostart_command_quotes_the_path`、`Autostart_points_elsewhere_reads_off`、`Autostart_disabled_by_system`、`Autostart_off_deletes_only_our_value`。

### Task 1: 工具链与 CellGlide.App 骨架（AOT 取舍、NuGet 许可清单）

**Files:**
- Create: `windows/CellGlide.App/CellGlide.App.csproj`、`app.manifest`、`Program.cs`、`App.xaml`、`App.xaml.cs`、`Shell/MainWindow.xaml`、`Shell/MainWindow.xaml.cs`、`packages.lock.json`
- Modify: `windows/Directory.Packages.props`（加 `Microsoft.WindowsAppSDK`、`H.NotifyIcon.WinUI`，以及构建要求的其他包）、`windows/CellGlide.sln`、`windows/CellGlide.Core/CellGlide.Core.csproj`（`None` 项加 `CopyToPublishDirectory="Always"`）
- Create: `scripts/check-nuget-licenses.ps1`、`packaging/licenses/nuget.txt`
- Modify: `scripts/check-windows-core.ps1`、`.gitignore`（如有新产物目录）、`docs/validation/windows-1.0.md`（新的「W3 界面」一节）

## 交给 Task 15 的 CI 增项

Task 15（`windows-x64`、`windows-arm64`）解锁后，在 W2 的增项（`setup-dotnet`、绑定一致性、`dotnet build`、`dotnet test`）之后加：
1. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check-nuget-licenses.ps1 -Check`。
2. `cargo build -p cg-ffi --release --locked`，然后在 `windows` 目录里 `dotnet publish CellGlide.App -c Release -r win-x64`（ARM64 运行器上 `-r win-arm64`）`-p:CellGlideNativeDir=..\target\release\`，检查输出目录有 `CellGlide.exe` 和 `cellglide_native.dll`。AOT 需要的 MSVC 链接器两种运行器都自带。
3. `dotnet build CellGlide.sln -c Debug` 已包含 App（按运行器架构），不需要另加。
`linux` 任务不用改。`scripts/gen-windows-icons.ps1 -Check` 不进 CI（GDI+ 的输出随 Windows 版本可能不同）。
