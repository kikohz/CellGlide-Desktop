# Windows 1.0 · W2 cellglide.dll Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出 `cellglide.dll`（新 crate cg-ffi）和不依赖 WinUI 的 C# 类库 CellGlide.Core，让一个控制台小程序经 DLL 跑通状态订阅、小数据量测速和 DNS 泄漏检测；界面需要的全部非显示逻辑都在 Rust 里，Linux 行为不变。

**Architecture:** cg-gui 里与 iced 无关、Windows 也要用的逻辑先搬进 `cg_ipc::describe::ui`、cg-tools 和 cg-diag，cg-gui 改为调用它们。cg-ffi 在 DLL 内起 tokio 运行时，经 cg-ipc 客户端连服务，在用户进程里跑测速、泄漏检测和诊断上传，把结果做成翻译好的视图模型，以 UTF-8 JSON 事件回调给 C#；C 接口只有 5 个函数。C# 端 CellGlide.Core 用 csbindgen 生成的 P/Invoke、System.Text.Json 源生成模型和 CommunityToolkit.Mvvm 视图模型包装 DLL，契约样例两边共用。W1 遗留给 W2 的项（上行 0.0 Mbps、管道实例复用、诊断脱敏缺口、严格 DNS 开关等）并入各任务。

**Tech Stack:** Rust 1.99（`x86_64-pc-windows-msvc`、`aarch64-pc-windows-msvc`、Linux CI），新增依赖：`csbindgen`（build-dependency）。.NET SDK 10.0.403，C# 类库 `net10.0`，CommunityToolkit.Mvvm，System.Text.Json 源生成，xUnit v3。PowerShell 5.1 脚本。

**Spec:** `docs/specs/2026-10-29-windows-1.0-design.md`（§4.1 的 cg-tools / cg-diag / cg-gui / cg-ffi 行、§7.3 的设置开关、§8、§9.1 的 Core 与 Tests、§11 与 §12.1 的 W2 部分、§14 的 W2 行）。功能和文案以 `docs/specs/2026-10-16-linux-1.0-full-design.md` §4 为准。前置阅读：`docs/superpowers/plans/2026-10-29-windows-1.0-w0-w1.md`（W1 已定的名字和约束）、`docs/validation/windows-1.0.md`（W1 实机记录，第 8 项是上行 0.0）。

**计划层面的决定（细化 spec，执行者照此做）：**
1. **共用逻辑的去处**：只依赖 cg-ipc 的放新文件 `crates/cg-ipc/src/describe/ui.rs`（`cg_ipc::describe::ui`），测速和泄漏的放 cg-tools 各自模块，诊断保存放 `cg_diag::save`。不新建 crate（spec §4.1 只给了 describe 和 cg-tools 两个去处）。搬的时候测试跟着搬，函数体不改；为去掉对页面 `State` 的依赖而改参数的，在 Interfaces 里写明新签名。
2. **语义色 `Tone` 放 `cg_ipc::describe::ui`**，只有名字（green、orange、red、blue、purple、gray），RGB 值留在 cg-gui 的 `kit` 和以后的 XAML 里。
3. **cg-ffi 的库名是 `cellglide`**（`[lib] name = "cellglide"`，产物就是 `cellglide.dll`）。spec 里写的 `cg_ffi::api` 即本计划的 `cellglide::api`。执行者裁定：Cargo 不能只改 cdylib 的文件名，构建后再改名容易出错。
4. **回调给 C# 的是视图，不是原始的 `cg_ipc::Response`**：`Request` 命令的回复里，doctor 变成检查行、history 变成一天的视图、diagnostics 带上文件名。执行者裁定：spec §2 反目标「C# 里不重复写 Rust 已有的逻辑」，渲染历史和检查项都是逻辑。
5. **每条命令恰好一个 `Reply`**（开始测速、开始泄漏检测也是：开始了就回 `done`，开始不了就回错误文字）；过程和结果另走 `SpeedProgress`、`LeakProgress` 事件。
6. **`SpeedStart` 带可选的 `caps`（小数据量上限）**。界面不传（用 Mac 的默认参数），控制台小程序和实机验收传。执行者裁定：§14 的出口要求小数据量测速，而完整测速一次约 1.3 GB 手机流量。
7. **控制台小程序用 C#（`windows/CellGlide.Probe`）**，经 CellGlide.Core 调 DLL。执行者裁定：这样走的是 W3 界面将来走的同一条 P/Invoke 和事件分发路径。
8. **严格 DNS 开关的协议和服务部分在 W2 做**（`Settings.strict_dns`、`SetSettings.strict_dns`，连接中改动立即生效）；W3 只加界面开关。执行者裁定：spec §7.3 写「W2/W3」，放 W2 让 W3 只碰界面。
9. **W2 不改 `.github/workflows/ci.yml`**。推送工作流文件要 GitHub 令牌的 `workflow` 权限，Task 15 还在等它。W2 的 CI 增项写成本地脚本 `scripts/check-windows-core.ps1`，并列在本计划末尾「交给 Task 15 的 CI 增项」，Task 15 解锁时一并加入。执行者裁定：同一个权限问题，分开改会推不上去。
10. **W1 遗留「settings.json 普通用户不可读」按设计关闭**：DLL 只从 `Snapshot.settings` 读设置，不读文件。

## Review Focus

1. **服务在 DLL 订阅期间停止、重启，或者从来没运行**：DLL 发 `ServiceGone`（文字说明原因），每 2 秒重试，服务回来后自动恢复 `State` 事件，C# 不用重新订阅；这期间发的 `Request` 在 10 秒内回 `Err` 文字，不会一直等。测试：Task 9 `service_restart_resumes_state`，Task 8 `request_to_a_missing_service_is_text`。
2. **C# 在测速或泄漏检测进行中调用 `cg_shutdown`、关闭后再 `cg_send`、重复 `cg_init`**：不崩溃，`cg_shutdown` 返回之后不再有任何回调，关闭后 `cg_send` 返回 0，第二次 `cg_init` 返回 `CG_ALREADY`；关闭后可以重新 `cg_init`。测试：Task 8 `no_events_after_shutdown`、`send_after_shutdown_returns_zero`、`init_twice_is_refused`、`init_again_after_shutdown`，Task 10 `shutdown_during_speed_test_is_clean`。
3. **C# 发来坏的命令**（不是 JSON、未知的 `type`、非 UTF-8、字段类型不对）**或命令处理里 panic**：回一条 `Reply { Err }`，panic 另发 `Fault`，DLL 照常处理后面的命令。测试：Task 8 `bad_command_replies_error`、`non_utf8_command_replies_error`、`panic_becomes_fault_and_err_reply`、`export_panics_never_unwind`。
4. **非英文 Windows 上的网卡别名**（「以太网」「WLAN 2」「Wi-Fi」）：上行网卡按别名选中，测速绑定按别名找到接口，界面里显示原名不乱码；USB 共享网络（iPhone 个人热点、Android RNDIS）不会被当成对比网卡。测试：Task 3 `picks_the_lowest_metric_physical_route`、`non_ascii_alias_survives`、`tethering_is_never_the_comparison`，Task 3 特权测试 `binds_by_localized_alias`。
5. **保存诊断时「下载」文件夹被 OneDrive 重定向、目标文件已存在、目录不可写**：用已知文件夹 `FOLDERID_Downloads` 的真实路径，不覆盖已有文件（加 `-2`、`-3`），失败时给出一句话，不留半个文件。测试：Task 2 `save_never_overwrites`、`windows_download_dir_is_the_known_folder`、`failed_write_leaves_no_file`。

- [ ] **Step 3: 按结论定修法**（写进验证文档，一行理由）

- 积压在我们进程里（②远大于③，或③远大于手机实际 `↑`、且是我们这边的套接字缓冲）→ 收紧那一层的缓冲：cg-netstack 的接收窗口，或 Windows 上转发器到 usbmux 的套接字 `SO_SNDBUF`（取实测能让 USB 跑满的最小值，例如 512 KiB）。改 cg-core / cg-netstack 时 Linux 行为不能变：值按 `cfg(windows)` 选。
- 积压在我们进程之外（AMDS 或手机）→ 引擎改为按服务器确认的字节计上行：每个 POST 的 `request_size` 降到 1 MB，收到 `__up` 的回复才把这 1 MB 计入；Mac 和 Linux 也用这个算法（这是计量修正，不是行为差异），在提交说明里写明。
- 不管哪种：测速结束、套接字关掉后，cg-netstack 必须**中止** SOCKS 一侧的连接（让转发器丢掉 usbmux 连接），不能让手机在测完后继续上传。

2. `cargo build -p cg-ffi --locked`，然后 `git diff --exit-code -- windows/CellGlide.Core/Native/NativeMethods.g.cs`（绑定与源码一致）。
3. `dotnet build windows/CellGlide.sln -c Debug`、`dotnet test windows/CellGlide.Tests --no-build`（ARM64 运行器上原生跑，`CellGlideNativeDir` 指向 `target\debug\`，那里是本机架构的 `cellglide.dll`）。
`linux` 任务不用改：`cargo test --workspace` 已包含 cg-ffi 的运行时和契约测试。
