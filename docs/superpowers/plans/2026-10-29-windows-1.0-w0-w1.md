# Windows 1.0 · W0 准备与实测 + W1 服务与隧道 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在这台 Windows 11 x64 测试机上，用 CLI `cellglide.exe connect` 经 Apple Mobile Device Service 连上 iPhone，让整台电脑走手机网络，DNS 只设在 cellglide0 上；断开、崩溃或卸载后，其他网卡的配置和之前完全一致；CI 在 x64 和 ARM64 上全部通过。

**Architecture:** 服务 `cellglide-service.exe`（LocalSystem，SCM 管理）复用 cg-core 控制器。新平台层 `cg-platform::windows` 负责 wintun 网卡、IP Helper 地址路由和 `SetInterfaceDnsSettings`；新 crate `cg-netstack`（ipstack + SOCKS5）把网卡上的包转给已有的 SOCKS 转发器。cg-ipc 增加命名管道传输，`server.rs` 改成与传输无关、按请求授权。W0 先把工具链、网络快照和几项关键行为实测清楚，结论写进验证文档，W1 的取值以它为准。

**Tech Stack:** Rust 1.99（`x86_64-pc-windows-msvc`、`aarch64-pc-windows-msvc`），新增依赖：`windows`（windows-rs）、`windows-service`、`ipstack`、`tracing-appender`、`etherparse`（只用于测试）。wintun 0.14.1 官方签名 DLL。PowerShell 5.1 脚本。pktmon（系统自带）。

**Spec:** `docs/specs/2026-10-29-windows-1.0-design.md`（§4–§7、§10.1、§11、§12、§13、§14 的 W0 与 W1 行、§14.1、§16）。前置阅读：`docs/windows/research-net.md`、`docs/windows/research-apple.md`。

**计划层面的决定（细化 spec，执行者照此做）：**
1. **W0 里能写成正式代码的部分直接写成正式代码。** wintun 封装、IP Helper、接口 DNS 是 W1 后端要用的模块，W0 就把它们写好、带测试，再拿它们做实测。纯为测量写的程序放在 `crates/cg-platform/examples/`，测完保留，供以后回归。
2. **服务最小特权集合挪到 W1 的 Task 14 测**（spec §14 写在 W0）。没有服务程序就测不了。
3. **cg-diag 的 Windows 脱敏规则提前到 W1 的 Task 13**（spec 写在 W2）。诊断包由服务打出，W1 的 CLI 就能导出它，脱敏不能晚于导出。
4. **Linux 专有代码（hev 对比测试、Linux 后端回归）只在 GitHub CI 上验证。** 这台机器没有 WSL 和 Docker。执行者推送 `windows` 分支后用 `gh run watch` 看结果。推送和 `gh` 需要用户先在这台机器上登录 GitHub（`gh auth login`），见 Task 1。
5. **wintun.dll 的查找顺序**：发布版只从程序所在目录加载；debug 版先看环境变量 `CELLGLIDE_WINTUN_DLL`（绝对路径），方便测试和示例从 `target\` 下运行。
6. **Windows 专用文案用「同名键加 `_windows` 后缀」**：`cg_i18n::tr_os(key, args)` 在 Windows 上若存在 `<key>_windows` 就用它，否则用 `<key>`。KEYS 测试保证两种语言都有。Linux 行为不变。

- **任何会改网络配置的命令（特权测试、示例、服务、安装脚本）前后都要跑 `scripts/network-snapshot.ps1` 并 `-Compare`，有差异就停下报告，不要自己去「修」别的网卡。**
- 隧道常量只从 `cg_core::tunnel` 取：`198.18.0.1/32`、`fd6c:6779:6465::1/128`、`0.0.0.0/1`、`128.0.0.0/1`、`::/1`、`8000::/1`、MTU 1500、TCP 读写超时 1800 s、UDP 空闲 30 s。

## Review Focus

1. **服务在连接中途崩溃或被 `taskkill /F`**：网卡、地址、路由、接口 DNS 都必须随进程消失，其他网卡快照不变；服务被 SCM 重启后能重新连接。测试：Task 11 `crash_leaves_nothing`（特权，子进程起后端后被强杀），Task 14 实机步骤。
2. **53 端口已被别人占用**（ICS / Hyper-V 的 SharedAccess 绑了 `0.0.0.0:53`）：连接要失败并给出 `Reason::ResolverPortBusy { port: 53 }`，已建的网卡和路由全部撤掉，不留半截隧道。测试：Task 11 `resolver_port_taken_rolls_back`。
3. **另一个会话或非活动会话里的普通用户发 Connect / Disconnect / SetSettings / Diagnostics**：回 `Reason::NotAllowed`；Status、Subscribe、History、Doctor 照常可用。测试：Task 12 `access_rules`、`read_only_peer_cannot_connect`。
4. **服务没运行时，别的程序抢先建了同名管道**：客户端必须拒绝它，报「不是 CellGlide 服务」，不发送任何请求。测试：Task 7 `refuses_server_that_is_not_system`。
5. **wintun.dll 缺失或不是官方签名的那份**：连接失败时给出能看懂的原因（不是 Windows 错误码），doctor 的 `Wintun` 项不通过并给出修复提示。测试：Task 3 `missing_dll_is_explained`，Task 13 `wintun_check_fails_without_dll`。

**Interfaces:**
- Produces（`cg_core::tunnel`，全平台编译，Windows 用）：
  - `pub const WINDOWS_ADAPTER_GUID: u128 = 0xE490EEF2_2CB0_4A80_B341_BF929C2E56B3;`
  - `pub const WINDOWS_TUNNEL_TYPE: &str = "CellGlide";`
  - `pub const WINDOWS_RESOLVER: SocketAddr = 198.18.0.1:53;`
- Produces（`cg_platform::windows::wintun`）：
  - `pub struct Wintun`：已加载的 DLL 和函数指针。`pub fn load() -> io::Result<Arc<Wintun>>`；`pub fn load_from(path: &Path) -> io::Result<Arc<Wintun>>`。
  - `pub struct Adapter`：`pub fn create(dll: &Arc<Wintun>, name: &str, tunnel_type: &str, guid: u128) -> io::Result<Adapter>`；`pub fn open(dll: &Arc<Wintun>, name: &str) -> io::Result<Option<Adapter>>`；`pub fn luid(&self) -> u64`；`pub fn start_session(&self, capacity: u32) -> io::Result<Session>`。`Drop` 调 `WintunCloseAdapter`。
  - `pub struct Session`（`Send + Sync`）：`pub fn read_event(&self) -> HANDLE`；`pub fn try_receive(&self) -> io::Result<Option<Vec<u8>>>`；`pub fn send(&self, packet: &[u8]) -> io::Result<()>`。`Drop` 调 `WintunEndSession`。
  - 常量 `pub const SESSION_CAPACITY: u32 = 0x40_0000;`（4 MiB）。

wintun 用 `windows` crate 的 `LoadLibraryExW`（`LOAD_LIBRARY_SEARCH_APPLICATION_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`）加 `GetProcAddress`，函数原型照 `wintun.h`（在 fetch 下来的 zip 里）。debug 版按决定 5 先看 `CELLGLIDE_WINTUN_DLL`。加载失败的错误信息要写明「找不到 wintun.dll，应与 cellglide-service.exe 放在同一目录」。

`scripts/fetch-wintun.ps1 [-Dest <dir>...]`：下载 `https://www.wintun.net/builds/wintun-0.14.1.zip` 到 `target\wintun\`，用 `Get-FileHash` 核对 SHA256（脚本里写死 wintun.net 公布的值；执行者从官网页面抄，抄完在验证文档里记一笔），解压后把 `bin\amd64\wintun.dll` 或 `bin\arm64\wintun.dll`（按 `-Arch x64|arm64`，默认本机）和 `LICENSE.txt` 复制到每个 `-Dest`。默认 `-Dest` 是 `target\debug`、`target\debug\deps`、`target\debug\examples`。

行为（对齐 hev 的 `udp: 'udp'`）：
- 每个 ipstack TCP 流：对 `config.socks` 发 SOCKS5 CONNECT（目标为原始目的 IP 和端口，不做 DNS），之后双向拷贝；两端都无数据超过 `tcp_timeout` 就关闭；一端半关闭时把 FIN 传到另一端。
- 每个 ipstack UDP 流：一条到 `config.socks` 的 TCP 控制连接发 UDP ASSOCIATE，本地 UDP 套接字按 SOCKS5 UDP 头封装收发；`udp_idle` 内无数据就关闭控制连接。
- SOCKS 连接失败时 TCP 回 RST、UDP 静默丢弃，记一条 debug 日志，不影响其他会话。
