# Windows 1.0 · W4 打包与发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Windows 版做成可以发布的 1.0.0：正式的 `install.ps1` / `uninstall.ps1`、`scripts/build-windows.ps1` 出的 zip 与 `SHA256SUMS`、完整的第三方许可、README 的 Windows 部分、CI 的 Windows 任务与发布构建、诊断服务端和官网接受 Windows（CellProxy），在这台机器上连 iPhone 过完整实机清单（含升级、卸载），最后在用户逐项同意后发布到 pkg.cellglide.com。

**Architecture:** 打包只在 `scripts/` 和 `packaging/windows/` 里加 PowerShell 与 Python 标准库脚本：`build-windows.ps1` 组装 zip，`install.ps1` / `uninstall.ps1` 各是一个独立文件（`irm | iex` 只能执行一个文件），`release-windows-json.py` 由两个 zip 生成 `SHA256SUMS`、`latest.json` 和官网用的 `release-windows.json`，`publish-windows.ps1` 用 wrangler 上传。纯函数用 Pester 5 测，真实安装与卸载由一个往返脚本在本机和 CI 运行器上跑。W3 留下的界面与 DLL 小项在前两个任务收掉；CellProxy 的两处改动在克隆里做、只提交不部署。

**Tech Stack:** Windows PowerShell 5.1（脚本目标环境，只用 ASCII）、Pester 5（≥ 5.5.0）、Python 3.12 标准库（`unittest`）、Rust 1.99、cargo-about 0.9.2、.NET SDK 10.0.403 + WinUI 3（W3 已定）、Node.js 22 便携 zip（不装进系统）+ wrangler（R2 上传 `wrangler@4.31.0`，与 `scripts/sign-and-publish.sh` 相同；部署用各项目自带的 wrangler）、GitHub Actions（`windows-latest`、`windows-11-arm`）。

**Spec:** `docs/specs/2026-10-29-windows-1.0-design.md`：§10（文件布局、install.ps1 第 1–10 步、卸载、未签名的问题）、§11（构建、`build-windows.ps1`、CI 表）、§12（Pester、CI 上的安装卸载、完整实机清单、§12.3 快照）、§14 的 W4 行、§14.1（用户答复）、§16（发布地址、`latest.json` 字段、只支持 Windows 11）。前置阅读：`docs/superpowers/plans/2026-10-31-windows-1.0-w3.md`（W3 的名字和规则）、`docs/superpowers/plans/2026-10-20-linux-1.0-m5.md`（Linux 发布流程，`release-linux.json`）、`docs/validation/windows-1.0.md`、`AGENTS.md`。

**计划层面的决定（细化 spec，执行者照此做）：**
1. **CI 改动单独成 Task 11，并以令牌的 `workflow` 权限为门槛**。2026-10-31 `gh auth status` 的权限只有 `gist`、`read:org`、`repo`。Task 1–10 不碰 `.github/workflows/`；Task 10 的实机清单用本机 `build-windows.ps1` 出的 zip；Task 11 是最后一个改代码的任务；Task 12 发布用 Task 11 里手动触发的 `windows-release` 运行产出的 zip。执行者裁定：发布要用 CI 产物（§14.1），所以发布只能排在 CI 之后；其余工作不必等权限。
2. **发布的字节就是测过的字节**。发布 CI 产物。Task 12 在上传门槛之前，把正要上传的两个 CI zip 原样装到本机，在其中的 x64 zip 上重跑 Task 10 清单的固定子集：安装、连接、DNS、每页都能打开、升级、卸载（Task 12 Step 2 的表）。上传的正是这两个 zip（按 SHA-256 核对）；标签打在产出它们的提交上。标签名 `windows-1.0.0`。执行者裁定：`1.0.0` 这个版本号已经是 Linux 的正式版，标签要带上平台。
3. **`install.ps1`、`uninstall.ps1` 各自是完整的单文件**。两者共用的函数（`Test-Elevated`、`Invoke-Native`、`Get-OurAdapter`、`Wait-AdapterGone`、`Stop-OurService`、`Remove-PathWithRetry`、`Remove-PhantomDevice`、`Select-ProcessesToStop`、`Test-ReparsePoint`、`Get-ReparsePoints`、`Refuse-ReparsePoint`）两边各放一份，Pester 测试 `Shared functions are identical` 逐字比较。执行者裁定：`irm | iex` 只执行一个文件，不能 dot-source 公共模块；用测试防止两份走样。
4. **提权分工**：第 1–3 步（系统检查、Smart App Control、Apple 设备、`winget`）和第 9 步的启动界面、第 10 步的 `doctor` 在用户自己的进程里做；第 4–8 步和启动服务在提权的子进程里做（`-ElevatedPart`），子进程把输出写进日志文件，父进程等它结束后原样打印。子进程运行的是父进程正在运行的这份脚本本身：脚本顶层把 `$MyInvocation.MyCommand.ScriptBlock` 的文本存进 `$CellGlideInstallText`（`-File` 和 `iex` 两种方式都能拿到），父进程把它写到 `%TEMP%\cellglide-install-<guid>.ps1` 再交给子进程；**不再从网上下载一次 `install.ps1`**（下载的脚本没有哈希可核对）。拿不到文本时报错退出，不退回下载。Task 5 的测试 `iex hands the script its own text` 证明 `iex` 下能取到；若它失败，换一种同样从内存取得自身全文的办法（例如顶层 `$CellGlideInstallText = $MyInvocation.MyCommand.Definition`），测试本身不改。用户本来就在管理员窗口里运行时，全部在一个进程里做，界面用 `explorer.exe` 转启。执行者裁定：`winget` 装商店应用和启动界面都要以真实用户身份；提权窗口一结束就关，`doctor` 的输出只有放在用户窗口里才看得到。
   **与 spec 的偏差（接受并记录）**：§10.2 把第 1–10 步写成一个提权进程依次执行，这里拆成用户进程与提权子进程；理由同上，步骤内容和顺序不变。
5. **下载地址可以覆盖，但只能指向本机**：`-BaseUrl` 参数或环境变量 `CELLGLIDE_PKG_BASE`，值必须是 `https://pkg.cellglide.com` 或 `http://127.0.0.1:<端口>`、`http://localhost:<端口>`。用于本机预演、实机清单和 CI 往返测试。执行者裁定：与 W3 的 `CELLGLIDE_DIAG_TARGET` 同一规则，不给任意主机留口子；环境变量是为了 `irm | iex` 也能用本地源。
6. **升级用整目录交换**：解压到 `C:\Program Files\CellGlide.new\`，旧目录改名为 `CellGlide.old\`，新目录改名为 `CellGlide\`，再删 `.old`；任何一步失败就把 `.old` 改回来、重启服务、报错退出。`app\` 因此整体替换，旧版多出来的运行时文件不会留下。执行者裁定：spec「整体复制」；交换比逐个覆盖多一层回滚，失败时旧版本照常可用。
7. **zip 里带 `version.txt`**（一行版本号）。`install.ps1` 用它写卸载项的 `DisplayVersion`，从网上装时还要求它等于 `latest.json` 的 `version`。同版本重装照常进行（打印 `Reinstalling`），降级照常进行（打印 `Downgrading`）。执行者裁定：`-ZipPath` 时没有 `latest.json`，版本只能从包里读。
8. **Smart App Control 处于强制模式时停止安装**（`HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 的 `VerifiedAndReputablePolicyState` 为 1），说明原因、指向以后的签名版，不改任何东西；评估模式（2）和关闭（0）照常安装。执行者裁定：强制模式会拦下未签名的服务和界面，装上也用不了。
9. **pdb 不进 zip**：`build-windows.ps1` 组装时跳过 `*.pdb`，另出 `CellGlide-<版本>-windows-<架构>-symbols.zip`，只作为 CI 产物保存，不上传。执行者裁定：W3 实测 pdb 27 MB；崩溃分析要用时从 CI 产物取。
10. **第三方许可**：
    - Rust 部分：`scripts/update-licenses.sh` 另生成 `packaging/licenses/windows-rust.txt`（cargo-about，配置 `packaging/licenses/about-windows.toml`，目标 `x86_64-pc-windows-msvc`、`aarch64-pc-windows-msvc`），没有 hev 与 C 代码。
    - NuGet 部分：`scripts/check-nuget-licenses.ps1` 另生成 `packaging/licenses/nuget-notices.txt`。开头是最终用户条款声明（`packaging/licenses/windows-end-user-notice.txt`，满足 Windows App SDK 条款 §3.b.ii），然后是每个随 App 发布的组件的许可全文和版权声明：锁文件里的包，加上不在锁文件里、但编进 `CellGlide.exe` 的 Windows SDK 投影 / CsWinRT。全文优先取包里的许可文件，没有时取 `packaging/licenses/nuget-texts/<id>.txt`（提交进仓库，取自对应版本的上游 LICENSE）。哪个都没有就失败。
    - zip 的 `THIRD-PARTY-LICENSES.txt` 和关于页（DLL 的 `licenses`）用同一份内容：`windows-rust.txt` 去掉首行，接 `nuget-notices.txt` 去掉首行。zip 版末尾多一节，指向 `wintun-LICENSE.txt`。
    - 执行者裁定：关于页也显示全文，用户在界面里看到的就是随包分发的全部声明；wintun 的许可本来就单独放在 `wintun-LICENSE.txt`。
11. **`CELLGLIDE_SPEED_CAPS` 留在正式版里**。执行者裁定：它只会把测速变小，不放宽任何东西；Task 10 和 Task 12 的实机测试用的就是正式版，必须靠它控制手机流量。README 不写它。
12. **托盘的键盘操作**：图标获得键盘焦点后按 Enter / 空格（`NIN_SELECT`、`NIN_KEYSELECT`），或按 Shift+F10 / 菜单键（`WM_CONTEXTMENU`），都打开面板，焦点落在面板的第一个控件上。执行者裁定：面板里有右键菜单的全部操作（连接/断开、打开 CellGlide、退出），也能用键盘操作；不必自己再画一个弹出菜单。
13. **侧栏圆点的读屏名称**：新键 `gui.badge_warning`（en `"Needs attention"`，zh-CN `"需要留意"`）和 `gui.badge_critical`（en `"Problem"`，zh-CN `"有问题"`）。C# 按 `Badge` 选键（`SidebarBadges.NameKey`），与按状态选托盘图标文件属于同一类显示映射。
14. **发布数据格式**（官网和安装脚本只依赖这些字段）：
    - `latest.json`：`{"version":"1.0.0","x64":{"url":…,"sha256":…,"size":…,"test_build":false},"arm64":{…,"test_build":true}}`。
    - `release-windows.json`：`{"version","date","install","uninstall","files":[{"kind":"zip","arch":"x64",url,size,sha256,test_build},{"kind":"zip","arch":"arm64",…}]}`，`files` 固定两项，顺序如上。
    - URL：`https://pkg.cellglide.com/windows/<版本>/CellGlide-<版本>-windows-<架构>.zip`。
    - 执行者裁定：`test_build` 放在数据里，ARM64 以后在真机测过时，只要重新生成数据，不必改 `install.ps1` 和官网代码。
15. **ARM64 以测试版发布**（§14.1）：没有 ARM64 电脑，Task 10 只测 x64。README、官网和 `install.ps1` 在 ARM64 上标明「测试版，没有在真机上测过」（en `"test build, not yet tested on real hardware"`）。
16. **新脚本测试用 Pester 5**（spec §12.1）。这台机器的 Windows PowerShell 只带 Pester 3.4.0，Task 4 用 `Install-Module Pester -MinimumVersion 5.5.0 -Scope CurrentUser -Force -SkipPublisherCheck` 装到当前用户；`scripts/test-windows-scripts.ps1` 统一运行。原有的纯脚本测试（`scripts/tests/test-*.ps1`）不改写，只有 `test-install-dev-datadir.ps1` 随 `Set-DataDirAcl` 搬进 Pester。
17. **`install-dev.ps1` 改成包装**：安装 = `build-windows.ps1 -Arch <本机>` + `install.ps1 -ZipPath <zip> -Unattended`；`-Uninstall [-Purge]` = `uninstall.ps1 [-Purge]`；去掉 `-Release`（总是 release）。执行者裁定：只留一条安装路径，开发时装的就是正式安装器装的东西。
18. **W4 不跑完整测速**，只用 `CELLGLIDE_SPEED_CAPS=small`；整个 W4 手机流量预算 **300 MB**。执行者裁定：沿用 W2、W3 的流量约束；小测速走的是同一个引擎。
19. **「信任这台电脑」不重测**：iPhone 早已信任这台电脑，重测要在手机上「还原位置与隐私」，会动用户手机的设置。清单里只核对 `doctor` 的 Trust 为 ✓，并在验证文档写明。**与 spec 的偏差（接受并记录）**：§12.2 的清单列有「首次信任」；W0 已记下信任与配对的结论（`docs/validation/windows-1.0-w0.md`「信任与配对结论」：只读配对记录，CellGlide 不发起配对），W4 不重复。
20. **安装和卸载脚本的输出只用英文**（ASCII）。执行者裁定：`.ps1` 只用 ASCII，Windows PowerShell 5.1 把没有 BOM 的文件按 ANSI 读，中文会乱码。
21. **CellProxy 克隆到 `C:\Users\iloss\CellProxy`**，在分支 `windows-1.0` 上改诊断服务端和官网。Linux 的改动当初在 Mac 上的分支 `diag-linux`（03e1ad6）和 `linux-download` 里做，未推送；2026-10-31 远端只有 `main`，没有 03e1ad6 这个提交，但 `main` 的 `Diagnostics/worker/src/index.js` 已有 `Linux` UA 与 `linux` 平台，`Website/build.py` 已有 `load_linux_release` 和 `id="linux"` 的下载区。所以 `windows-1.0` 从「含有这些 Linux 改动的分支」切出：克隆后先跑 Task 8 Step 1 的核对；`main` 含有就从 `main` 切，不含就看远端有没有 `diag-linux` / `linux-download`，都没有就停下请用户把 Mac 上的两个分支推上来。两个部署门槛都要写明部署内容包含 Linux 部分。DNS 泄漏服务按用户所说已经对 Windows 返回 200，只核对、不改。
22. **不往系统里装软件**：Node.js 用官方便携 zip，解到 `%LOCALAPPDATA%\CellGlide-dev\node\`（核对 `SHASUMS256.txt`），只在当前会话的 PATH 前面加上它；wrangler 一律经这个 Node 的 `npx` 运行。Pester 装到当前用户（决定 16），不算全机安装。
23. **开发机上的 `-Purge` 前先备份**：凡是会在这台机器上执行 `uninstall.ps1 -Purge` 的步骤，先把 `C:\ProgramData\CellGlide\` 和 `%LOCALAPPDATA%\CellGlide\` 用 `robocopy /E /COPYALL`（连 ACL 和所有者一起）备份到 `%LOCALAPPDATA%\CellGlide-dev\backup-<时间>\`，卸载后、重新安装前原样拷回（重新安装会重设 ProgramData 的 ACL），并核对文件数与 `speedtests.json`、`settings.json` 的 SHA-256 与备份前相同。
24. **卸载不加载别的用户的注册表配置单元**：Run 值只从 HKCU 和 `HKU` 下已加载的用户配置单元里删；不 `reg load`。没登录的用户的 Run 值留下，它指向一个已不存在的 exe，登录时什么都不会发生（写进 README 的卸载说明）。`-Purge` 删每个用户的数据只针对 `ProfileList` 里、路径位于 `ProfilesDirectory`（通常 `C:\Users`）之下的配置文件，路径校验不过或是 junction 的拒绝。

## Global Constraints

- `AGENTS.md` 全部适用：只动 cellglide0（固定 GUID `{E490EEF2-2CB0-4A80-B341-BF929C2E56B3}`）的地址、路由、跃点和 DNS；不用 NRPT；不碰其他网卡；卸载时删除该 GUID 的 `Tcpip` / `Tcpip6` 接口键；崩溃时依靠网卡消失。安装和卸载脚本只碰 CellGlide 自己的服务、文件、网卡、注册表项（服务、卸载项、我们 GUID 的接口键、各用户 Run 下指向我们 exe 的 `CellGlide` 值），不碰 Apple 设备。
- **凡是安装、卸载、升级、连接、断开、切换严格 DNS、让隧道掉线再恢复的步骤，前后都跑 `scripts/network-snapshot.ps1` 并 `-Compare`**，有差异就停下报告；基线当天新拍。每一次安装都算，包括测试结束时把开发安装装回去的那一次。
- **对外动作每一项都是单独的步骤，写明「先停下问用户，等用户明确同意」**，未经同意不执行：推送 main 或向 main 开 PR（两个仓库都算）；打发布标签；上传到 pkg.cellglide.com；部署 CellProxy 的诊断服务或官网；向正式诊断服务 `diag.cellglide.com` 发送诊断；向微软提交误报申诉；删除 R2 里的任何对象。克隆私有的 CellProxy 仓库并在本地修改、提交不需要问。推送 `windows` 分支不需要问。
- **手机流量**：iPhone 一直插在这台电脑上。W4 禁止完整测速，只用 `CELLGLIDE_SPEED_CAPS=small`；预算 300 MB；每次实测把用量（`cellglide.exe status` 的「本次会话」前后差）记进验证文档。隧道连着时整台电脑的流量都走手机，实测之外的时间保持断开。
- **测试和脚本从不写真实的 `HKCU\…\Explorer\StartupApproved\Run` 键**；注册表测试只用 HKCU 下随机命名、用完删除的临时键。卸载脚本也不碰 `StartupApproved`（那是 Windows 写的）。
- iPhone 协议由 iOS app 定义，一律不改。cg-ipc 的 `PROTOCOL_VERSION = 6` 不变。隧道常量、cg-netstack 的 MTU 与超时不动。
- C# 端不重新推导 DLL 已经给出的东西（spec §8.1）；界面上的用户可见文字只在 `crates/cg-i18n/locales/{zh-CN,en}.yml`，新键两种语言都要有并加进 `cg_i18n::KEYS`。DLL 与 C# 之间的消息只在 `cellglide_native::api`，改字段就同时更新 `crates/cg-ffi/tests/fixtures/`（`CG_FFI_BLESS=1 cargo test -p cg-ffi --test fixtures` 重写后逐个看差异）和 `windows/CellGlide.Core/Models/`；字段 snake_case，`Option` 序列化为 `null`。panic 不跨 C 接口。
- 版本号只有一个来源：`Cargo.toml` `[workspace.package] version`，W4 保持 `1.0.0`。
- Rust 任务结束前：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo test --workspace --locked`。`Cargo.lock` 一变就在 Git Bash 里跑 `bash scripts/update-licenses.sh`（Task 3 起它同时写 `packaging/licenses/windows-rust.txt`），一并提交。
- C#：dotnet 命令一律在 `windows\` 里执行；`powershell -NoProfile -ExecutionPolicy Bypass -File scripts\check-windows-core.ps1` 通过（无警告、全部测试通过、许可检查通过；Task 4 起也跑 Pester）。NuGet 中央包管理、锁文件、`--locked-mode` 照旧；新包必须是宽松许可。
- `.ps1` 只用 ASCII（没有大于 0x7F 的字节），运行方式 `powershell -NoProfile -ExecutionPolicy Bypass -File <脚本>`，每个会话先 `. scripts\dev-env.ps1`。所有文本文件 LF 换行。Python 只用标准库，以 `-I` 运行；这台机器的 Python 在 `%LOCALAPPDATA%\Programs\Python\Python312\python.exe`，不在 PATH 上时用完整路径。
- 构建产物不进仓库：`dist/`（已在 `.gitignore`）放 zip 和发布数据，`target/`、`windows\**\bin\`、`windows\**\obj\` 照旧。
- 代理的 shell 在会话 0，WinUI 在那里起不来：界面实测照 W3 用临时交互计划任务（`schtasks /it /ru iloss`）在会话 1 启动，用完删除。需要 UAC 确认、注销登录、按电源键、拔插线的步骤由控制者请用户操作。

def make_dist(root: Path, arches=("x64", "arm64"), bad_sum_for=None) -> Path:
    for arch in arches:
        name = f"CellGlide-1.0.0-windows-{arch}.zip"
        data = f"zip bytes {arch}".encode()
        (root / name).write_bytes(data)
        digest = "0" * 64 if arch == bad_sum_for else hashlib.sha256(data).hexdigest()
        (root / f"SHA256SUMS.{arch}").write_text(f"{digest}  {name}\n", encoding="utf-8")
    return root
