# CellGlide Desktop development constraints

- DNS changes must be confined to CellGlide's own resolver and its own TUN link (`cellglide0`). Never change Wi-Fi, Ethernet, other adapters, other VPNs, `/etc/resolv.conf`, or saved NetworkManager connections.
- On Linux, set DNS only through systemd-resolved per-link calls on our TUN link (`SetLinkDNSEx`, `SetLinkDomains`, `SetLinkDefaultRoute`), revert with `RevertLink` on stop, and rely on the link disappearing on crash. No legacy DNS restoration logic. Return real DNS addresses rather than fake IPs.
- Verify other links' DNS, `/etc/resolv.conf` and NetworkManager connection files are identical before and after installation/testing.
- The iPhone protocol is defined by the CellGlide iOS app; do not change the phone side from here.
- Keep tunnel constants (addresses, routes, MTU, hev settings) identical to the macOS app's tunnel configuration.
- On Windows, set DNS only through `SetInterfaceDnsSettings` on cellglide0 (fixed GUID), clear it on stop, and delete that GUID's interface key on uninstall; on a crash, rely on the adapter disappearing. Do not use NRPT, and do not change other adapters' DNS, metrics, or routes.
- On Windows, acceptance uses `scripts/network-snapshot.ps1` to compare other adapters' DNS, NRPT, metrics, routes, and Tcpip interface keys before and after.
- On Windows, the forwarding engine is cg-netstack; its MTU and timeout parameters stay consistent with the hev settings.
- On Windows, while connected, a WFP dynamic session (`FWPM_SESSION_FLAG_DYNAMIC`) blocks outbound port 53 on physical adapters only (strict DNS): interface types Ethernet 6, Wi-Fi 71 and mobile broadband 243/244, except adapters of those types that are not hardware (virtual: Hyper-V vEthernet, TAP, WAN miniports), which get a permit by LUID; Bluetooth PAN counts as physical. A PPPoE dial-up link (PPP, type 23, over a NIC) is blocked by LUID; the built-in PPP VPNs (PPTP, L2TP, SSTP, IKEv2) are not. Other VPNs and virtual adapters (Tailscale, WireGuard, other wintun adapters) keep their port 53; loopback and cellglide0 are permitted. Its rules vanish with the session handle or the process; never add persistent WFP objects.
- On Windows, wireless sessions use one temporary access point: a Wi-Fi Direct group owner with legacy settings (`WiFiDirectAdvertisementPublisher`), started only when the user asks for a wireless connection (or briefly, to check the wireless switch can work), stopped when the session ends, and gone with the process on a crash. When an iPhone on USB takes a connected wireless session over, that session is held rather than ended: the access point stays up (so the iPhone stays joined) until that iPhone is unplugged, when the session resumes on it, or until the user disconnects, cancels, picks another connection or switches wireless off, or the computer sleeps, when it stops; on wake, if that iPhone is still on USB, the access point starts again, held the same way. Never turn on Windows Mobile Hotspot or Internet Connection Sharing, never disconnect or change the Wi-Fi network the computer is on, and never write addresses, DNS, routes or metrics on the Wi-Fi Direct virtual adapter. The Wi-Fi Direct virtual adapter's own entries (what Windows itself sets on it) are left out of the snapshot comparison, like cellglide0's.
- Strict DNS and this temporary access point are the only system-wide network effects allowed.
